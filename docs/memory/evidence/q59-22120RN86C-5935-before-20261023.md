## Notes

- Command: `py -3.12 -I -u tools/memory/q59_late_open_check.py -s bek749scrwv4wo8h --tag before`. Host debug 5935 built from `9f31f2c79` (without the Q59 change) and re-signed with the host signing config so that it installs over the device's host.
- "After settling" is counted 40 s after the last run, past the 30 s idle unbind of the pooled connections, so what is left are dedicated bindings of plugin sessions that nobody closes.
- Gallery, YOLO, Mail and EPUB keep one dedicated binding for each stop that came while the plugin was still opening and whose session the plugin returned afterwards (Gallery 8, YOLO 1, Mail 4, EPUB 8). Scripts see it: after the first late YOLO session every later `yolo.load` failed with `YOLO_SESSION_OPEN_FAILED` (the provider's single session is taken, 16 runs), and after 8 late EPUB books every `epub.open` failed with `EpubError [LIMIT_EXCEEDED]` (14 runs); both last until the plugin process ends.
- AutoJs4 releases without the change too: its engine's forceStop only sets the stopped flag, so a stop never cancels the admission call (no stop landed inside it) and the engine cancels the admitted script itself. The window closed by the change opens only when the admission answers after its 75 s deadline (60 s plus the 15 s accept timeout), which the runtime plugin does not do here; `AutoJs4LateAdmissionTest` covers it on the JVM.
- EPUB is served by `readium.epub.reader` 1.2.0, the EPUB plugin installed on the device. The generated 3000-chapter book keeps the opening at about 11 s so that stops land inside it.
