## 失败项逐条判定

| 项 | 现象 | 判定 | 处理 |
|---|---|---|---|
| Bun 全列 | `INSTALL_FAILED_OLDER_SDK` | API 33 限制: 官方二进制调用 `close_range`, Android 12L 及更早的应用 seccomp 以 SIGSYS 结束进程 | 矩阵 minApi 规则 `bun-plugin-min-sdk`; 文档站 "执行方式" 表写明 |
| `notice.channel` (及 `notice.channel.getAll`) | Node main / Worker 抛 `No virtual method hasUserSetImportance()Z` | **真缺陷**: 该方法 API 29 才有, 版本判断写的是 P (API 28), 正好在 API 28 上崩 | 6d9fd7546 改为 Q, 复测 51 / 51. Rhino 的 `notice.channel` 更新路径 (Channel.kt) 有同样的判断, 一并修 |
| `terminal.open` (用例 terminal.session) | 偶发 `no output line matched within 15000 ms`: 首轮 Node main 超时, 次轮 Rhino 超时 | 不是 API 限制: 每次 transcript 都有输出. `waitFor` 只从调用时刻订阅, 回显更早就错过 (探针命中 Rhino 0 / 8, Node 6 / 8) | 用例改为写入 1 s 后才打印 (Node 5587b94e), 连续 3 轮全过; Node 的竞态登记 Q227 |
| `zip.zipFile` (zip 组 47 个用例) | Node 写 `/sdcard` 报 EACCES | 不是 API 限制, 是授权前置条件: 插件有自己的 UID, 设备上没授存储权限, 也没有应用内申请流程 | 维护者在系统设置授权后 184 / 184, 抽样结束已撤销; 文档站写明; 登记 Q228 |
| img-transport | 首轮 `AssertionError: Bun` | 测试问题: 用例后半段是 Bun 专属 | 6d9fd7546 在 API 33 以下跳过, 复测通过 |
| js-tools 11 个 `global.*` 用例 | Rhino 基线报 `Cannot find module` | 不是 API 限制: 设备没装 Bundled Libraries; 临时安装后第二轮报插件未启用 | 宿主重装后的最终轮 524 过 / 0 败 |
| plugin-family `theme.current` / `theme.set.options` | 首轮 libraryId 1 与 33 不一致 | 用例顺序: Rhino 首轮把库状态从 Default 变成 Palette, Node 轮次看到的是后者 | 第二轮起全过, 不影响抽样项 `colors.theme.set` |

版本判断顺查: `engine`, `core/plugin`, `runtime/api/modules` 下其余 14 处 `VERSION_CODES.P` 判断 (`longVersionCode`, `getProcessName`, `getStreamMinVolume`, `GET_SIGNING_CERTIFICATES` 等) 都确为 API 28 接口, 只有 `hasUserSetImportance` 两处写错. Channel.kt 那一处带 `@SuppressLint("NewApi")`, 所以 lint 没有报出来.
