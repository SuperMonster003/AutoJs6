# APK Builder Template Plugin Repository

This document describes the split repository deployment for the AutoJs6 APK Builder template plugin.

## Ownership Boundary

AutoJs6 remains the only source of truth for the INRT runtime and script engine source. The APK Builder template plugin repository must not keep a second copy of the AutoJs6 runtime source.

The cross-repository boundary is the Runtime Kit generated by the main repository:

```text
app/build/runtime-kit/autojs6-runtime-kit-v<version>+<code>.zip
```

The kit contains:

```text
template.apk
template.apk.sha256
default_key_store.bks
default_key_store.bks.sha256
runtime-kit.json
build-contract.json
public-api.txt
assets-manifest.json
native-libs.json
provenance.json
```

## Main Repository Tasks

Generate a kit locally:

```powershell
.\gradlew.bat --console=plain :app:generateRuntimeKit
```

Build the current monorepo distribution without embedding `template.apk` in the main app APK:

```powershell
.\gradlew.bat --console=plain assembleApkBuilderTemplateDistribution
```

The app APK does not include the built-in template by default:

```properties
autojs.apkBuilder.includeBuiltInTemplate=false
```

Set it to `true` only for local compatibility debugging.

## Release Flow

`.github/workflows/release-runtime-kit.yml` runs on `v*` tags and manual dispatch.

It does the following:

1. Builds `:app:generateRuntimeKit`.
2. Uploads `autojs6-runtime-kit-*.zip` as a workflow artifact.
3. Uploads the same zip files to the same-tag Release of `SuperMonster003/AutoJs6-Runtime-Kits`, creating that Release when needed and removing older kit files from it.
   The AutoJs6 Release itself carries only the host APKs: users kept downloading the kits there by mistake (moved on 2026-11-03).
   The kit repository must not be an `AutoJs6-Plugin-*` repository, because the official plugin index treats every Release there as a plugin version.
4. Sends `repository_dispatch` to `SuperMonster003/AutoJs6-Plugin-APK-Builder-Template` with `tag`, `source_repo` and `runtime_kit_repo`.

Secrets in the main repository:

```text
AUTOJS6_PLUGIN_REPO_TOKEN
AUTOJS6_RUNTIME_KIT_REPO_TOKEN (optional)
```

`AUTOJS6_PLUGIN_REPO_TOKEN` must have `Contents: write` permission on `SuperMonster003/AutoJs6-Plugin-APK-Builder-Template`, which is required by GitHub's repository dispatch endpoint.
The kit upload uses `AUTOJS6_RUNTIME_KIT_REPO_TOKEN` when it is set and `AUTOJS6_PLUGIN_REPO_TOKEN` otherwise; that token needs `Contents: write` on `SuperMonster003/AutoJs6-Runtime-Kits`.
In `SuperMonster003/AutoJs6` a missing token fails the run instead of skipping the upload or the dispatch.

Do not rerun the `v6.8.0` tag run: the workflow file at that tag still uploads the kits to the AutoJs6 Release.
The `v6.8.0` kits already live in `SuperMonster003/AutoJs6-Runtime-Kits`; run the plugin repository's `build-from-runtime-kit.yml` to republish the plugin.

## Plugin Repository Build

The standalone plugin repository should download and unzip the Runtime Kit, then build the plugin with:

```bash
./gradlew :plugins:apk-builder-template:assembleRelease \
  -Pautojs.apkBuilder.templatePlugin.runtimeKitDir=runtime-kit
```

In the standalone repository this becomes:

```bash
./gradlew :app:assembleRelease \
  -Pautojs.apkBuilder.templatePlugin.runtimeKitDir=runtime-kit
```

The plugin Gradle task verifies:

```text
runtime-kit.json
template.apk SHA-256
default_key_store.bks SHA-256
required APK entries
```

At runtime the plugin reads:

```text
assets/runtime-kit/runtime-kit.json
assets/runtime-kit/template.apk
assets/runtime-kit/default_key_store.bks
```

## Plugin Repository Workflow Skeleton

```yaml
name: Build APK Builder Plugin from Runtime Kit

on:
  repository_dispatch:
    types:
      - autojs6_runtime_kit_released
  workflow_dispatch:
    inputs:
      tag:
        required: true
        description: AutoJs6 tag, for example v6.7.1

permissions:
  contents: write

jobs:
  build:
    runs-on: ubuntu-latest

    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-java@v4
        with:
          distribution: temurin
          java-version: "21"
          cache: gradle

      - id: vars
        run: |
          if [ "${{ github.event_name }}" = "repository_dispatch" ]; then
            echo "tag=${{ github.event.client_payload.tag }}" >> "$GITHUB_OUTPUT"
            echo "runtime_kit_repo=${{ github.event.client_payload.runtime_kit_repo }}" >> "$GITHUB_OUTPUT"
          else
            echo "tag=${{ inputs.tag }}" >> "$GITHUB_OUTPUT"
            echo "runtime_kit_repo=SuperMonster003/AutoJs6-Runtime-Kits" >> "$GITHUB_OUTPUT"
          fi

      - name: Download Runtime Kit
        env:
          GH_TOKEN: ${{ secrets.AUTOJS6_MAIN_REPO_TOKEN }}
        run: |
          mkdir -p runtime-kit
          gh release download "${{ steps.vars.outputs.tag }}" \
            --repo "${{ steps.vars.outputs.runtime_kit_repo }}" \
            --pattern "autojs6-runtime-kit-*.zip" \
            --dir runtime-kit
          unzip runtime-kit/autojs6-runtime-kit-*.zip -d runtime-kit

      - name: Build plugin APK
        run: |
          ./gradlew :app:assembleRelease \
            -Pautojs.apkBuilder.templatePlugin.runtimeKitDir=runtime-kit

      - name: Publish plugin release
        env:
          GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
        run: |
          tag="${{ steps.vars.outputs.tag }}"
          gh release view "$tag" >/dev/null 2>&1 || gh release create "$tag" --title "APK Builder Plugin $tag"
          gh release upload "$tag" app/build/outputs/apk/release/*.apk --clobber
```

Required secret in the plugin repository:

```text
AUTOJS6_MAIN_REPO_TOKEN
```

The token must be able to read AutoJs6 release assets when the main repository is private. For a public repository, `GITHUB_TOKEN` or unauthenticated `gh release download` may be enough.
