## 2. 分屏退出的生产根因与修复

修复前的 target 36 包 SHA-256 为
`95499d4de139d04f026e1ebb57bbe81733e1517005dc8f09bd2db617d2105f11`.
普通手机旋转正常, 平板进入分屏后 UI 脚本消失.

`explore-script36-tablet-v2` 记录旧实例 `215974785` 因配置变化销毁,
新实例 `167756058` 带 saved state 创建, 随即再次销毁, 当前 Activity 变为 null.
另外使用 IDEA 非暂停日志断点, 在正常启动完成后附加到 PID 10395,
`debug-script36-tablet-late` 得到以下实际值:

| 时间 (UTC) | 位置 | 读到的值 |
| --- | --- | --- |
| 2026-09-13 23:56:09.812 | ScriptExecuteActivity.kt:251, onDestroy | `changing=true, mask=2432` |
| 2026-09-13 23:56:13.619 | ScriptExecuteActivity.kt:139, execution 类型判断前 | `execution=null` |
| 2026-09-13 23:56:14.139 | 新实例 onDestroy | `changing=false, mask=0` |

2432 = orientation (128) + screenLayout (256) + smallestScreenSize (2048).
原 manifest 只声明 `orientation|keyboardHidden|screenSize|locale`, 漏掉后两项.
生产 `onDestroy` 会销毁脚本引擎并移除执行对象, 新 Activity 按旧 executionId 查找时得到 null,
从而结束. 该链路在无调试器及后附加调试器两种运行中均出现.

修复仅给 `ScriptExecuteActivity` 补齐 `smallestScreenSize|screenLayout`.
视图仍根据新窗口尺寸重新布局, 当前脚本和视图状态保留.
没有把同样的 flags 批量加给 Main / Edit / Log, 没有添加全局强制弹键盘策略.
宿主和 inrt 的共享 manifest、最终 APK 二进制清单均确认 configChanges 为 `0xda4`.
这不保证进程死亡、主题 / 字体 / density 等其他配置变化后的脚本自动恢复.

## 3. target 36 / 37 的实际矩阵

共选择 20 组, 即 5 个入口 x 2 种窗口尺寸 x 2 个宿主 target, 均为 compat 默认态.
按最终状态与布局标准, **4 组 UI 脚本通过, 其余 16 组保留失败 / 待处理项**.
旧 runner 曾只检查文本与 dirty, JSON 保留 `reportedSuccess`, 并对全部记录重新计算
`validationErrors` / `validatedSuccess`; 不沿用旧成功标志掩盖光标或布局问题.

| 入口 / 形态 | target 36 与 target 37 的共同观察 | 判定 |
| --- | --- | --- |

当前源码与回调相符: Main 处理 orientation / screenSize / screenLayout, 未声明 smallestScreenSize;
Edit 处理 orientation / screenSize, 未声明 screenLayout / smallestScreenSize;
Log 没有 configChanges 声明. 原生编辑器的草稿服务保存 / 恢复文本,
不能据此推断已经覆盖光标或 Ace 的异步恢复链路. 首次记录时, 除 UI 脚本外的上述问题尚未完成根因修复,
也没有证据把它们归因于 target 37 新增行为.

普通 UI 脚本的手机横屏 IME 使用 fullscreen extraction, 可见标志为 true 但 bottom inset 为 0,
截图实际显示提取输入区和键盘. 因此不以 inset=0 单独判断键盘未出现.
原生编辑器的可滚动文本子视图可以超过父 viewport, 几何判断使用 engine view 的可见区域;
日志页则直接检查实际输入栏. 一旦 viewport 为 0 或输入栏位于键盘区域, 整组不判通过.

## 4. 官方规则与实测边界

[Android 17 大屏说明](https://developer.android.com/about/versions/17/changes/ff-restrictions-ignored)
说明 target 37 在 sw >= 600dp 移除方向 / 尺寸限制的旧豁免.
本项目没有使用该豁免, 两个 target 的默认手机 / 平板方向对照符合预期.
本轮没有新增豁免属性再切换兼容开关, 不将默认态结果写成独立开关的正反对照.

[配置变化官方说明](https://developer.android.com/guide/topics/resources/runtime-changes)
将 Android 17 减少重建的具体变化列为 keyboard、keyboardHidden、navigation、touchscreen、
colorMode, 以及进入 / 离开 desk 的 uiMode. `recreateOnConfigChanges` 可选择恢复对应重建行为.
这不意味着屏幕尺寸变化一概不再重建. 当前资源目录未见针对这些硬件 / desk / 色彩模式的
专门限定版本, 但目录扫描和本轮旋转 / 分屏不能代替真实外设配置变化测试.

[Android 17 全体应用变化](https://developer.android.com/about/versions/17/behavior-changes-all)
将 IME 默认不恢复限定在配置变化导致 Activity 重建的情况.
本轮 Log 旋转重建后 IME 消失, Script / Edit 自行处理旋转时仍可见;
据此修正 Roadmap 中笼统的 "旋转后不再恢复" 表述. 没有给所有 Activity 设置
stateAlwaysVisible, 仍需按实际输入焦点和产品流程处理恢复.

悬浮窗 / 悬浮控制台、拖动分屏分隔条 / 自由窗口、复杂字体、物理键盘、触摸板捕获、
IME 组合输入、真实返回手势与完整边到边布局尚未验收.
Xiaomi API 35 平板及 API 37 真机均未运行本轮测试, UI01-UI04 的实体机清单保持开放.
