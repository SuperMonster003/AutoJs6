# Android SDK 37 P2.8: 存储与文件管理器

日期: 2026-09-13. 会话起点 `16ba3901f`. 正常配置仍为 compile 37 / host target 36 / inrt target 29. [机器结果](android-sdk-37-p28-results-20260913.json) 保存实际 APK、脚本和原始证据的 SHA-256, 以及各组断言和失败探索. 原始日志、截图、APK 和设备字节码保留在忽略目录 `build/sdk37-p28-p210/`.

有效矩阵共 12 组、84 次行断言执行: 存储 8 组 x 9 项, target 36 / 37 选择器各 4 项, 拒绝 / 授权状态各 2 项. 包含重复对照, 不是 84 个独立业务场景. 失败、超时、较早夹具及被后续验证替代的结果单独保存, 不计入此数.

## 1. 三个开关的实际作用范围

本轮从 `CE2A.260420.019` 镜像拉取实际 MediaProvider、ContactsProvider APK 和 `framework-mediaprovider.jar` 检查字节码, 不用 AOSP main 分支代替该镜像. 兼容配置中的三个名称与 `enableSinceTargetSdk=37` 均存在, 但不能据此把三个开关都归为文件管理器权限.

| 开关 | 当前镜像的实际检查 | 对 AutoJs6 的影响 |
| --- | --- | --- |
| `EXCLUDE_UNRELIABLE_STORAGE_VOLUMES` (391360514) | `MediaStore.getExternalVolumeNames(context)` 调用 `StorageManager.getStorageVolumes()`, 对 mounted / mounted_ro 卷取 MediaStore 名称. 同时满足应用 compat 和平台 `excludeUnreliableVolumes` flag 时, 跳过目录路径以 `/mnt/` 开头的卷 | 不是修改 `StorageManager.getStorageVolumes()` 本身. 宿主文件管理器生产代码未直接调用此 MediaStore 卷枚举入口. 脚本可以通过 Android API 调用它 |
| `REQUIRE_PERMISSIONS_FOR_DIRECTORY_QUERIES` (157720069) | ContactsProvider2 在向联系人目录提供方转发查询前, 按该目录提供方的 package / user 检查 compat, 并检查提供方的权限. 电话查找分支要求 `READ_CALL_LOG`, 联系人查找要求 `WRITE_CONTACTS` | 不是 MediaStore 或 DocumentsContract 的目录权限. 宿主没有实现这种联系人目录提供方. 普通 `ContactsContract.Directory.CONTENT_URI` 的 READ_CONTACTS 拒绝对照不代表命中此门控 |
| `TRASH_BEHAVIOR_CHANGE` (461429441) | MediaProvider 的 `isCallingPackageTargetSdkVersionGreaterThanB()` 同时检查调用应用 target > 36 和 provider 进程中的单参数 `CompatChanges.isChangeEnabled(long)`. FileUtils 的相关路径使用 `.trash-storage` | 宿主 target 36 即使 enable 仍使用原位置的 `.trashed-*`; target 37 使用 `.trash-storage`, 单独 disable 宿主开关仍不回退. AutoJs6 自己的回收站和历史存储不通过 MediaStore `IS_TRASHED` 实现 |

字节码的关键信息、包版本和哈希见机器结果 `platform`. 官方 [Android 17 目标版本变更](https://developer.android.com/about/versions/17/behavior-changes-17) 是背景资料, 未提供以上三个开关的完整定义; 本表只对所测镜像负责.

## 2. 实际功能断言

复跑入口见 `14a594b10` 的 [工具说明](../../../tools/sdk37/README.md#storage-widgets-and-notification-views). `run_framework_probe.py --suite storage` 在真实 Rhino 引擎中执行九项检查, 每项都必须有成功的独立回执. 只有 APK 启动、兼容开关配置或日志无异常不能通过.

| 项目 | 实际调用与断言 |
| --- | --- |
| `files.*` | 在新建共享目录中写入中文文件名和 UTF-8 内容, 读回、复制、重命名和删除, 比较实际内容 |
| 文件管理器 | 生产 `ExplorerFileProvider` 列举该目录, `PathChecker` 接受实际文件 |
| 卷与模拟 SD 卡 | 分别记录 StorageManager 和 MediaStore 卷列表; 主卷已挂载, 模拟 SD 卡 `/storage/0000-0000` 上实际写入、读回和清理中文文件 |
| 版本历史 | 生产 `HistoryRepository` 和 Room DAO 保存一条新版本, 读回字节、恢复文件, 清理并确认记录消失 |
| 应用回收站 | 生产 `TrashRepository` 移入、确认原文件消失、恢复字节并确认回收站记录移除 |
| 图片保存与扫描 | `images.save` 保存 16x12 PNG, `media.scanFile` 后查询刚创建的 MediaStore 行并断言尺寸 |
| 系统媒体回收站 | 对刚创建的行设置 / 查询 `IS_TRASHED`, 记录真实 `_data` 与过期时间, 恢复原文件路径, 删除测试行 |
| 联系人基线 | 未授予 READ_CONTACTS 时, 普通联系人目录查询按实际权限被拒绝; 不将此项算作远程目录门控的正反例 |
| 所有文件访问入口 | 生产权限助手的 `has()` 与 `Environment.isExternalStorageManager()` 一致, 应用专属 Settings Intent 可解析 |

target 36 默认态及三个开关分别独立 enable 均通过九项检查. target 37 默认态和仅 disable 宿主 TRASH 开关也通过. 宿主开关在每次执行前后记录, 新版工具还拒绝不符合显式预期或执行中变化的状态. 普通 SD 卡的通过不能证明不可靠 USB 卷被排除.

系统媒体行的实际路径:

```text
target 36: /storage/emulated/0/Pictures/.trashed-<expiry>-sdk37-<case>.png
target 37: /storage/emulated/0/.trash-storage/Pictures/.trashed-<expiry>-sdk37-<case>.png
恢复后:   /storage/emulated/0/Pictures/sdk37-<case>.png
```

## 3. 选择器与权限 UI

选择器工具使用实际 `ScriptExecuteActivity.startActivityForResult` 和 `ui.emitter` 回调. 文档选择核对返回 URI 的实际 UTF-8 内容, 获取并释放 persistable read grant; 取消要求 RESULT_CANCELED 且无 URI. 系统 Photo Picker 读取本轮新建的 18x14 图片, 用每轮不同的像素颜色核对内容; 取消同样不能返回 URI. 此验证不等于 WebView File System Access API 的 chooser / 授权验证.

`allfiles` 工具检查生产权限助手与平台值, 并从前台 Activity 调用 `AllFilesAccessPermission.request()`, 由 runner 核验应用专属 Settings 页面实际位于前台. 本轮只在已识别为 AutoJs6 的页面上关闭 / 重新开启开关. 关闭时 ActivityManager 明确记录 `Killing ... org.autojs.autojs6 ... MANAGE_EXTERNAL_STORAGE changed`, 因此不能等待同一进程返回关闭后的回执; 拒绝 / 授权状态在重启后的独立进程验证. 旧版授权探针虽然返回 true, 截图仍为 Launcher, 只证明助手读到授权状态, 不计入完整 UI 成功组. [target 37 拒绝截图](android-sdk-37-p28-p29-screens-20260913/allfiles37-denied-verified.png) 和 [target 36 重新授权截图](android-sdk-37-p28-p29-screens-20260913/allfiles36-granted-verified.png) 分别对应实际助手回执; 重新开启的 UI 层级与 AppOps 也单独保存. Settings 在此镜像会跳转到 SpaActivity, 工具核验实际页面标题、AutoJs6 名称及唯一开关状态, 不固定最终 Activity 别名.

## 4. 环境、失败探索与范围

- 独占只读 `AVD_API_37`, console 5586, x86_64, `-no-snapshot-load -no-snapshot-save -no-window -no-audio`. fingerprint 为 `google/sdk_gphone16k_x86_64/emu64xa16k:17/CE2A.260420.019/15611780:userdebug/dev-keys`.
- `getconf PAGE_SIZE=16384`, 实际内核页大小 4096; 不能计入真实 16 KB 内核验收.
- 初版图片夹具缺少 `ImageWrapper.ofBitmap` 的 runtime 参数; 后续 UI 图片夹具遇到 Rhino 对 `Bitmap.eraseColor(int/long)` 的重载选择, 已显式指定 int 签名. 没有因此修改生产图像 API.
- MediaStore 行可能先于扫描后的宽高元数据出现. 最终存储探针等待本次图片的 16x12 元数据完整后才进行回收 / 恢复; 仍有 15 秒截止时间, 超时保存最后观察到的尺寸. 初版过早断言失败单列保存.
- 最终 target 36 包的首轮后台存储探针超时. 系统明确记录 `20:38:26 freezing` 与 `20:42:50 sync unfroze`, 随后原脚本完成全部九项; 超时结果与迟到回执仍列为诊断. 存储工具改为可见 Activity 中的工作线程, 并核验结束时前台窗口, 避免缓存进程冻结干扰功能断言.
- 后续模拟器反复出现 `failed to complete startup` ANR, 尚未执行测试脚本. DropBox 的主线程栈涉及 AppCompat 类初始化、ART 类校验及 finishAttachApplication, 完整记录已保存. 在仅限本轮的已安装 target 36 APK 上执行 `cmd package compile -m speed -f` 成功后复测; 不改 APK、平台策略或 compat. 这些启动失败不计入存储断言, 也不凭此断言生产存储存在回归.
- ADB 服务中途重建导致连接丢失; 所有功能操作始终指定本轮 `127.0.0.1:5587`, 未操作已连接的手机. 后续改用独立 ADB 5053. 失败测试遗留的 DocumentsUI / Photo Picker 会留在原脚本 task 中, 阻止后续 UI 脚本正常启动; 清理本轮系统选择器后重跑.
- UIAutomator 在界面切换中可能返回 exit 0 但无 XML. 工具现检查真实输出、有限重试, 并等待 / 核验选择器前台窗口. 文档取消需要先返回上级目录, 不能把一次 Back 当成 RESULT_CANCELED; 本镜像 Photo Picker 在选中图片后还需显式点击 Done. 延迟出现的说明横幅可能下移图片网格, 工具从新层级重新定位图片, 在操作前再次核验待处理回调, 最多三次, 不沿用旧坐标. 下一次选择器启动前等待宿主窗口恢复焦点. 失败测试遗留任务仅在确认其单一根组件属于宿主且位于 user 0 后移除, 清理结束后再 force-stop / 启动新测试.
- 最终 target 36 复跑暴露了过快连续 Back 的问题: 文档取消后排队的 Back 结束了 ScriptExecuteActivity, 随后的相册结果失去接收方. 主进程 `finished` / `onDestroy` 与平台冻结日志均已保留. 驱动改为每次 Back 前核验选择器焦点、等待回调; JS 的 activity_result 在回调到达时立即清除对应 request 的 pending 状态. 这属于测试取消时序修正, 未修改生产 Activity 生命周期.
- 本轮没有发现需要修改生产存储代码的 SDK 37 回归. 未改变公开 JS API、权限模型或 Gradle 依赖, 不需要额外的文档站 / d.ts 发布.

仍需实体机 / 外设验收: 不可靠 USB / OTG 卷、拔出和只读切换, OEM 文件管理器与选择器, 旧 API / inrt 成品应用. 当前 AVD 的普通模拟 SD 卡结果不关闭这些项目. 具体范围继续由 [实体机清单](../android-sdk-37-physical-device-tests.md) 管理.

工具判定测试 8/8、既有设备工具测试 4/4 与 Python 编译检查通过. 选择器时序补充提交为 `855134388`. 结束时四个所测宿主 compat 均恢复 target 36 默认值, 本轮权限 / 小组件绑定授权已移除, 独占只读 AVD 与私人 ADB 5053 已关闭; 共享 ADB 5037 与连接的手机未做修改. 清理回执和进程身份见机器结果, 99 行实体机清单仍为 NOT_RUN.
