## 2. 官方规则与本轮实测

VERIFIED: Android 17 对所有应用要求可见 Activity 或非 `shortService` 前台服务; target 37 的后台路径再要求 WIU 能力. 精确闹钟授权与闹钟用途有独立例外. 系统可静默抑制播放 / 音量, 焦点请求则返回失败. `enable` / `throw` 会改变所有 target 与闹钟例外的规则, 必须与默认结果分开. [官方后台音频说明](https://developer.android.com/about/versions/17/changes/bg-audio).

所有下表记录的 `mHardeningOverride` 在前后快照中均为 0. 焦点 1 表示成功, 0 表示失败. "未静音" 仅表示本次系统播放器记录没有音频强化静音, 不表示物理扬声器已验收.

### 2.1 音量不能代替播放资格查询

该失败场景的系统记录为:

```text
AudioHardening volume control for api 100 would be ignored ... level: full usage: 0 exemption: 4
AudioHardening focus request for req 3 ignored ... level: full usage: 1 exemption: 0
AudioHardening background playback muted ... level: full, reason: 0, usage: USAGE_MEDIA
```

DEVICE-37: 在此镜像和精确闹钟授权状态下, 公开音量 API 被记为 usage 0 / exemption 4, 媒体音量仍实际改变. 同时普通媒体焦点与播放已被阻止. 不把这个镜像的豁免推论为所有 Android 17 设备都允许后台修改媒体音量, 也不凭音量写入成功判断可以播放.

`AudioTrack.write()` 在被静音场景仍返回 16000, 播放状态仍为 3, 播放头也前进. 同样不能用 `isMusicPlaying()` 或进度推导实际发声. 本轮没有给现有 API 增加基于这些信号的误判拦截, 也没有为探测资格额外抢占用户音频焦点.

### 2.2 恢复与 TTS 进程

DEVICE-37: 普通媒体闹钟入口的活动服务记录为 `getFgsAllowWiu_forCapabilities=DENIED`. 回到可见 Activity 再调用生产 `ForegroundService.start()` 后, 同一 PID 的活动服务记录变为 `PROC_STATE_TOP`, 再切后台焦点成功. `dumpsys activity services` 还含此前的历史 ANR 服务, 机器可读证据仅提取当前 PID 的活动服务块.

产品指引使用现有界面: 打开应用, 在侧边栏启用前台服务; 若后台启动的服务仍在运行, 在可见界面关闭后重新开启并重试脚本. inrt 的设置页使用同一服务封装, 其完整打包应用路径留给后续设备验收.

DEVICE-37: TTS 宿主 PID / UID 为 10124 / 10340, 实际 `CONTENT_TYPE_SPEECH` 播放器来自 `com.google.android.tts`, PID / UID 为 4131 / 10164. 本轮只验证该引擎的初始化, 入队与完成回调, 未验证其他引擎或无人值守可听性. SOURCE: `AndroidTtsBackend` 委托系统引擎播放, `synthesizeToFile` 独立合成文件, 不应仅根据宿主 FGS 状态拒绝文件合成.

## 3. 实施选择与代码审计

- Q3 按原推荐方案 (a) 推进: 保留通用 `specialUse` 常驻服务, 在现有帮助与 API 文档中提供恢复操作及已知限制. 不将通用自动化服务整体改成媒体专用服务. 真正的媒体播放服务需单独管理播放与焦点生命周期, 并考虑 Android 15 起 `mediaPlayback` 的开机启动限制. [官方服务类型说明](https://developer.android.com/develop/background-work/services/fgs/service-types#media).
- SOURCE: `Media.java` 的 `playMusic` / `resumeMusic` 直接使用 `MediaPlayer`, 不自动启动 FGS. `Device.java` 三类音量 setter 使用 `AudioManager.setStreamVolume`, 正常返回本身不代表音量改变.
- SOURCE: Node `dispatchMedia` 的音量桥也调用 `AudioManager`. 既有 Node 播放策略拒绝尚未具备独立焦点生命周期证据的播放 provider; 本轮未开放该能力.
- SOURCE: `TimedTaskScheduler` 的 Alarm / WorkManager / Job 后端最终运行脚本, 未自动建立音频 FGS. 宿主 `BootCompletedReceiver` 初始化调度器; inrt 开机接收器经项目启动器运行应用. 上述入口不能等同于已经获得 WIU.
- SOURCE: `settings.setEnabled('foreground_service', true)` 写入偏好值; 不是服务启动或 WIU 查询 API. 已补正文档边界.
- 宿主前台服务帮助补齐 11 份字符串资源, default / en 一致. 当前版本 10 语言 `improvement` 已更新并生成 README / CHANGELOG.
- API 文档更新 Media / Device / TTS / Settings, 同步 Progress / Changelog. 无公开 API 签名变化, d.ts 无需变更.
- 离线插件独立发行版已为 6.8.1, 内容仍为 AutoJs6 6.8.0. 生成器修复 `2d0ed0d` 保留插件发行版本, 继续严格验证内容版本和两份 provenance; 3 项回归测试通过.

## 4. 探针与复跑

`AudioCompatibilityProbeActivity` / Receiver 仅位于 debug 源集. 最终 Activity 要求 `android.permission.DUMP`, Receiver 不对其他应用导出; 系统 BOOT_COMPLETED 仅在手工 arm 后执行一次. 最终探针另补齐 boot 的 TTS 选项持久化及异常后的独立音量读回.

`tools/sdk37/run_audio_probe.py` 要求专用模拟器和 debuggable 包, 不安装 APK, 不自动变更音频强化模式. 它使用新输出目录, 清理自身旧结果, 创建新的探针 Activity, 检查场景身份, 保存系统状态并独立断言焦点与音量. `recover-service` 保留进程和服务; `arm-boot` 会重启所选模拟器.

```powershell
# target 37 仅用于 debug 探针; target 36 构建时省略覆盖参数.
./gradlew :app:assembleAppDebug '-Pautojs.sdk.target.override=37'

# 选择专用 API 37 AVD, 按 output-metadata.json 选择并安装 APK.
# adb 需位于 PATH; Python 工具也支持 --adb 指定完整路径.
adb -s emulator-5566 shell appops set org.autojs.autojs6 WRITE_SETTINGS allow
adb -s emulator-5566 shell pm grant org.autojs.autojs6 android.permission.POST_NOTIFICATIONS
python tools/sdk37/run_audio_probe.py --serial emulator-5566 --scenario visible-service --expect allowed --output build/sdk37-p22/new-visible-service
python tools/sdk37/run_audio_probe.py --serial emulator-5566 --scenario background --expect blocked --output build/sdk37-p22/new-background
python tools/sdk37/run_audio_probe.py --serial emulator-5566 --scenario alarm-stream --expect allowed --output build/sdk37-p22/new-alarm-stream

# 先实际核对 dumpsys audio 的覆盖状态; 不把 exit 0 当作已启用.
adb -s emulator-5566 shell cmd audio set-enable-hardening throw
adb -s emulator-5566 shell dumpsys audio
python tools/sdk37/run_audio_probe.py --serial emulator-5566 --scenario background --expect diagnostic-errors --output build/sdk37-p22/new-throw
```

默认用例必须读取到 `mHardeningOverride=0`. `diagnostic-errors` 要求非默认覆盖状态, 并验证音量 / 焦点抛出 `IllegalStateException` 及写入返回负值. 此镜像的普通媒体闹钟场景可另用 `--expect focus-blocked-volume-allowed`, 但仍需审阅系统静音事件, 不用这个断言掩盖平台差异.
