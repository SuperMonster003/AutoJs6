## 6. 打包链路回归: `resources.arsc`

现象: 第一次用插件打出的示例 APK 在 API 37.1 安装失败:

```text
Failure [INSTALL_PARSE_FAILED_RESOURCES_ARSC_COMPRESSED: Targeting R+ (version 30 and above) requires
the resources.arsc of installed APKs to be stored uncompressed and aligned on a 4-byte boundary]
```

原因: 插件 `RemoteApkLightweightBuilder.packageUnsignedApk` 用 `ZipOutputStream` 默认 DEFLATED 写入全部条目; inrt 目标 29 时系统不检查, 目标 37 起 (Android 11+ 的 R+ 规则) 直接拒绝. apksig 会保留 STORED 条目及其对齐, 所以只需在未签名 APK 阶段处理.

修复: 新增 `RemoteUnsignedApkWriter` (`resources.arsc` 以 STORED 写入, 通过 zipalign 同款 `0xD935` 扩展字段把数据起点补到 4 字节边界, 其余条目与 `META-INF` 过滤规则不变), 并落到两份源码:

| 副本 | 改动 | 验证 |
| --- | --- | --- |
| `AutoJs6-Plugin-APK-Builder-Template` (独立仓库, 协议 3) | `impl/RemoteUnsignedApkWriter.kt` 重写; `RemoteUnsignedApkWriterTest` 新增 `resourceTableIsStoredAndFourByteAligned` (文件名长度 1..4 四种偏移) | `:app:testDebugUnitTest` 38/38; `:app:assembleDebug`; `generate_markdown.py --check`、`check_repository.py --pending-commit` 通过; 提交 `ce6dfd9` (v1.0.3, VERSION_BUILD 42) |
| 宿主 `plugins/apk-builder-template` (仓内旧快照, 协议 2) | 同名 writer 与测试新增, `RemoteApkLightweightBuilder.packageUnsignedApk` 改为调用 writer, 删除 `addApkDirectoryToZip` / `shouldSkipUnsignedApkEntry` | `:plugins:apk-builder-template:testDebugUnitTest` 2/2 |

修复后产物核对 (第 7 节的三个 APK): `zipalign -c -v 4` 全部 `Verification successful`, `resources.arsc` method STORED、extra `35d9...`、数据偏移 4 字节对齐; `apksigner verify` V2 通过 (插件默认签名密钥, 证书 `c4530b8e...`).

## 8. 发现: 正式构建路径尚未落地 (WATCH)

- 插件仓库 `docs/plugin-managed-apk-build-architecture.md` (ADR, 2026-09-02 已采纳) 规定唯一正式路径按 `supportsApkBuild` / `apkBuilderBuildProtocolVersion` / `APK_BUILD_VERSION` 准入, 不读实验性宿主总开关, 也不依赖 `supportsRemoteBuild`; 官方插件发布 `supportsApkBuild=true` + `supportsRemoteBuild=false`, 仓库 `gradle.properties` 已固定 `enableRemoteBuild=false`.
- 宿主 HEAD 没有这条路径: `BuildActivity.callApkBuild` 只调用 `RemoteApkBuildClient.buildBlocking`, 后者先读 `RemoteApkBuildRuntimeGate` (`key_apk_builder_remote_build_enabled`, 默认 false), 再要求插件 `supportsRemoteBuild=true` 且协议 >= `REMOTE_BUILD_VERSION` (3); 宿主与插件源码中都没有 `supportsApkBuild`. 旧的进程内 `ApkBuilder` 回退已移除.
- 结果: 按仓库既定配置构建的插件 (v1.0.2 发布件亦如此) 在 HEAD 宿主的打包页面一律 NOT_AVAILABLE ("does not advertise compatible experimental remote APK building"). 本次示例打包与打包页面走同一条 `buildBlocking` 路径 (生产测试打开开发者开关并指定插件包名), 插件用 `-Pautojs.apkBuilder.templatePlugin.enableRemoteBuild=true` 构建 (插件仓库 `docs/remote-build-rollout.md` 记载的启用方式). 宿主与插件谁先迁移到 ADR 的正式键位由维护者决定, 不在 P3 / D7 范围; 在此之前, 发布件需带 `enableRemoteBuild=true` 或宿主先落地 `supportsApkBuild` 准入.
