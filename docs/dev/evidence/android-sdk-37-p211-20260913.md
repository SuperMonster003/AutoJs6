## 2. 正式矩阵

开关均为 `ENABLE_USER_AGENT_REDUCTION` (371034303).
`default` 表示没有该包的显式 override; 未修改 DeviceConfig / aconfig.
每个宿主组包含 4 种 `ui.webview` UA 设置方式及 2 个实际文档页:

- `default`: WebSettings 初始值.
- `custom`: `ui.web.attr("userAgent", "AutoJs6-SDK37-WebView-Probe/1.0")`.
- `suffix`: `userAgentString` 属性设置为默认 UA 加 ` AutoJs6-SDK37-Probe/1.0`.
- `reset`: 先设自定义值, 再调用公开 `WebSettings.setUserAgentString(null)` 恢复默认.
- 文档: `https://offline-docs.autojs6.local/index.html` 与 `app.html`.

| 宿主实际 target | 宿主 override | 默认 UA 预期与实测 | UI 四种方式 | 文档两页 | 合计 |
| --- | --- | --- | --- | --- | --- |
| 36 | default | 未缩减 | 4/4 | 2/2 | 6/6 |
| 36 | enabled | 缩减 | 4/4 | 2/2 | 6/6 |
| 37 | default | 缩减 | 4/4 | 2/2 | 6/6 |
| 37 | disabled | 未缩减 | 4/4 | 2/2 | 6/6 |

HTML Previewer 保持自身 target 36, 独立增加 4 个场景:

| 宿主 target / override | 插件 target / override | 插件页面默认 UA 预期与实测 | 结果 |
| --- | --- | --- | --- |
| 37 / default | 36 / default | 未缩减 | PASS |

HTML 插件仍为 target 36, 这些结果不能关闭 P5 的 target 37 最终包验收.

## 3. 验证内容与结论

`run_webview_probe.py` 使用 Python 标准库, 通过本机临时 adb forward 连接真实 WebView DevTools.
每次生成新的 case ID、脚本 receipt 和 HTML 目录, 先停止宿主 / HTML Previewer,
再以新任务启动 Rhino 脚本. 不使用同名旧文件或启动请求成功作为完成证据.

UI 路径同时比较 `WebSettings.userAgentString`、`navigator.userAgent` 和 HTTP 服务实际收到的
`User-Agent` 头. 三条来源在四种设置方式下完全一致. 自定义字符串保持原值;
追加后缀保留当前默认值的缩减状态; reset 恢复相应 target / override 的默认值.

实测未缩减值:

```text
Mozilla/5.0 (Linux; Android 17; sdk_gphone16k_x86_64 Build/CE2A.260420.019; wv) AppleWebKit/537.36 (KHTML, like Gecko) Version/4.0 Chrome/145.0.7632.218 Mobile Safari/537.36
```

实测缩减值:

```text
Mozilla/5.0 (Linux; Android 10; K; wv) AppleWebKit/537.36 (KHTML, like Gecko) Version/4.0 Chrome/145.0.0.0 Mobile Safari/537.36
```

上述行为与 [Android 官方 WebView 说明](https://android-developers.googleblog.com/2024/12/user-agent-reduction-on-android-webview.html)
相符. 网页不应把缩减后的 Android 10 / K 当作实际 OS 或型号; 给默认 UA 追加后缀也不会恢复这些信息.
需要额外设备信息时可评估 User-Agent Client Hints; 官方说明的支持条件为 WebView 116+ 且使用默认 UA.

实际两个 HTTPS 文档来源均可读取 `navigator.userAgentData`, 即使默认 UA 已缩减,
本机返回的 `platformVersion=17.0.0`, `model=sdk_gphone16k_x86_64`,
`fullVersionList` 中 WebView / Chromium 为 145.0.7632.218. `architecture` / `bitness` 为空.
这些是当前 provider 的观测值, 不是所有 WebView 版本或字段必定可得的承诺.
HTTP `10.0.2.2` 来源不是 secure context, 该路径返回 null, 不用它判定 UA-CH 支持与否.

每个正式场景均检查 DOM 完成、页面尺寸、预期内容、当前前台窗口并保留 PNG.
UI / HTML 还检查新 case 标记、CSS 色块尺寸与颜色及本地 `#details` 导航.
文档实际首页有 254 个链接, App 页有 432 个链接, 并核对所请求的 URL.
另人工查看了 8 张代表截图, 确认页面可见、基本布局正常且没有系统对话框遮挡;
这不是对全部字体、触摸或键盘交互的验收.

代表截图: [UI target 37](android-sdk-37-p211-20260913/ui-target37-default.png),
[文档首页](android-sdk-37-p211-20260913/docs-index-target37-default.png),
[App 文档页](android-sdk-37-p211-20260913/docs-app-target37-default.png),
[HTML 插件启用缩减](android-sdk-37-p211-20260913/html-plugin36-enabled.png).

HTML 使用现有 Explorer Action v2 契约, 仅授予新建夹具目录的读取权限.
实际页面来源为 `https://appassets.androidplatform.net/html-document/__previewer__.html`.
预览器默认禁用文档 JavaScript, 夹具为静态 HTML; DevTools 读取 DOM / UA 并未打开产品的交互模式.

源码复核: `WebViewAttributes.kt:36` 直接把 `userAgent` / `userAgentString` 交给公开 WebSettings;
文档及 HTML 预览加载不需要通过 UA 型号字符串选择资源. 本轮未发现需要生产代码修复的 UA / 渲染差异.

## 4. 探索失败与工具修正

[机器结果](android-sdk-37-p211-results-20260913.json) 明确选择 28 个正式结果,
另保存 13 个未接受的探索结果, 包括早期 `success=true` 的记录, 不用简单统计布尔值来计算通过率.

- 初始 AVD 出现 System UI ANR 对话框. 早期 DOM / HTTP 校验通过也不能证明无遮挡渲染.
  在本轮独占设备上关闭该系统对话框后, 补入前台窗口检查并重新执行正式矩阵.
- 初始 HTML 夹具错误使用 ACTION_VIEW, 后改为插件实际支持的 Explorer Action v2;
  DevTools URL 过滤也改为实际 `appassets.androidplatform.net` 来源. 错误入口与未找到页面的结果均保留.
- 上一轮 HTML 位于同一个跨 UID 任务时, 只停止宿主可能带回旧任务而不执行新脚本.
  工具现在停止两包并以 `NEW_TASK | CLEAR_TASK` 启动, 无本 case receipt 就失败.
  这项夹具隔离不能替代 P2.5 的实际 ASM / BAL 验收.
- 禁用文档 JavaScript 的 HTML 页面不会完成本轮 DevTools 动画回调等待; 改用 300 ms 原生绘制等待并检查截图.
  插件进程启动也改为有界轮询, 避免 receipt 写入后立即 `pidof` 的启动竞态.
  两个失败的正式候选目录保留, 成功复跑使用 `-v2` 新目录.

8 项 Python 测试全部通过, 覆盖旧 receipt、缺页 / CSS、HTTP / DOM 不一致、错误默认 UA 预期等拒绝条件.
Python 编译检查通过. 修改只涉及验证工具与研发文档, 不触发产品 changelog、Documentation / d.ts 生成或插件版本递增.
