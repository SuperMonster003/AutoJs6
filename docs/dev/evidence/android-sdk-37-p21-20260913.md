## 官方前提与实现

官方要求 target <= 36 的应用不要声明或申请 `ACCESS_LOCAL_NETWORK`; 这些版本通过 INTERNET 保留隐式访问. 因此使用按 flavor 实际 target 选择的 [manifest overlay](../../../app/src/target37/AndroidManifest.xml), 正常 host / inrt 包不包含该权限. API 37 / target 37 包才声明并请求它. [Local network permission](https://developer.android.com/privacy-and-security/local-network-permission).

新权限属于 Nearby Devices 组. 拒绝时 TCP 常表现为超时, UDP 可返回 EPERM; TCP 服务端的入站 accept 同样受限. 系统选择器对用户选择的设备可提供有限访问, 不能替代任意脚本 socket 或 LAN 监听器的权限. [Local network permission](https://developer.android.com/privacy-and-security/local-network-permission).

平台按接口、路由和地址共同判断本地网络; Wi-Fi / Ethernet 与 cellular / VPN 的待遇不同. 诊断中的地址判断只是提示条件, 不提前拦截脚本连接, 不把公网 IPv6 或主机名失败直接断言为权限问题. [Local network definition](https://developer.android.com/privacy-and-security/local-network-definition).

同 profile 的 IPv4 / IPv6 loopback 在本轮拒绝和授予场景都可用. Android 17 的跨 profile loopback 限制另行存在, 不能据此推导工作资料宿主与个人资料插件互通. [Android 17 enterprise changes](https://developer.android.com/work/versions/android-17).

[LocalNetworkPermission.kt](../../../app/src/main/java/org/autojs/autojs/permission/LocalNetworkPermission.kt) 按 OS 与 target 双重条件工作. 抽屉、宿主设置与 inrt 设置提供入口. VS Code 用户显式连接或开启服务器时才引导; 自动连接和脚本网络调用不自动弹窗. 拒绝后可以重试, 连续拒绝后提供系统设置按钮, 不自动跳转设置. 请求回调随 Activity 生命周期释放.

Q1 按 Roadmap 已写明的 "默认按推荐项" 执行为 (a), 并非再次取得了维护者单独投票. 复用已有的 `runtime.requestPermissions(["access_local_network"])`; 该方法异步返回 void, 授权完成后由脚本重新执行操作. 未新增 JS 函数或权限结果回调.

[LocalNetworkDiagnostics.kt](../../../app/src/main/java/org/autojs/autojs/core/http/LocalNetworkDiagnostics.kt) 为实际失败的 HTTP、WebSocket 与 Node controlled fetch 附加恢复提示, 保留原异常 cause. TLS 失败和用户取消不会被标为权限失败. 原生 Java Socket 与 Paho 保留原始 OS / 库异常; 文档给出显式申请和重试步骤.

## 发现并修复的 Node 超时问题

首次设备探针中, 未授权 LAN 请求在 OkHttp 的整次调用超时后被记录为 `ERR_AUTOJS6_NETWORK_ABORTED`, 文案为 `AutoJs6 controlled fetch was cancelled.`. 原因是整次调用超时也会让 `call.isCanceled()` 为 true, 既有分支将它当作主动取消, 丢掉了原始异常及恢复提示.

修复区分 OkHttp 的整次调用 timeout 与显式取消. 现在前者保留 `ERR_AUTOJS6_NETWORK_TIMEOUT` 并带本地网络权限提示; 主动销毁请求仍走取消路径. 拒绝权限的真实设备测试与既有 `NodeFetchBridgeInstrumentationTest#androidFetchProviderCancelsActiveLiveRequestOnDestroy` 均通过. 这里不表示所有超时都是权限问题, 错误提示仍带条件说明.

尝试 JDWP logpoint 时没有取得可用内部状态记录; 诊断依据是无调试器的实际失败结果、源码分支与修复后的设备回归. 两次等待调试器引发的测试进程 ANR 不计入应用正常运行的缺陷或通过证据. 临时断点、run configuration 与端口转发均已清理, 原有用户异常断点保留.
