# 16 KB deployment evidence, 2026-09-11

Status: local implementation and the checks below passed. The roadmap remains open for the full
runtime matrix and a physical arm64 device whose page size is 16384.
Machine-readable artifact hashes, gate reports and exact user APK results are in
[page-size-16kb-20260911.json](page-size-16kb-20260911.json).

## Build and static verification

All 42 plugin repositories have passing native-alignment reports, with no skipped gate. The final
cross-repository scan reports **0 failing 64-bit entries** across 43 repositories.
The scanner samples the latest APK per variant directory and also checks source-tree native inputs;
the Gradle gate independently checks every output declared by each assembled variant's metadata.
Python's report includes the Chaquopy native modules inside nested ZIP / IMY assets.

Five Runtime Kits (universal, arm64-v8a, armeabi-v7a, x86_64, x86) passed ELF checks and SDK
`zipalign -c -P 16 -v 4`. Each contract declares `nativeLibPageAlignment=16384`.
The host and generated user APKs retain DEFLATED native libraries and `extractNativeLibs=true`.
The old host APK failed the new gate as intended.

## Unit and device checks

- Host: 19 focused JVM tests passed (ELF parser/policy, build diagnostics, plugin center semantics, Image Quantization compatibility).
- Shared plugin: 11 alignment/manifest tests passed; the wider plugin check also passed before publication.
- APK Builder: the ZIP writer regression test passed for both manifest extraction values; native entries remain compressed and service metadata survives signature removal.
- Official index: 28 tests passed.
- API 36 x86_64: `PAGE_SIZE=16384`, linker compatibility `false`, PM compatibility disabled. Host terminal / OpenCV / image quantization, Python ssl/sqlite3/ctypes, center badge, and a Rapid v3 user APK passed.
- API 37 x86_64: `PAGE_SIZE=16384`, linker compatibility `fatal`, PM compatibility disabled. The same host and Python checks passed. ImGui semantic rendering, QuickJS language execution, Node host execution, MediaInfo snapshot reading, TypeScript Binder compilation, and Lua sequential sessions passed. Lua's initial mismatched debug signer was correctly rejected; a release fixture signed with the host identity passed without relaxing trust checks.
- Xiaomi 23046RP50C arm64/API 35: `PAGE_SIZE=4096`. Host, Python and badge checks passed. A real user APK executed PTY shell exit 37, image quantization, Paddle v3 and Rapid v3/v6. Both OCR engines returned `["测试"]`.
- Real user APKs were generated by the remote APK Builder, signed, installed and executed. API 37 additionally passed without selecting a separate OpenCV plugin, proving Rapid's optional OpenCV payload is copied. Final rebuilt Runtime Kit runs passed on API 37 and Xiaomi; see `user-apk-final-*` entries in JSON.
- Negative runtime guard: a test plugin contained the preserved NDK r26b Image Quantization JNI library (`PT_LOAD=4096`). Its current manifest still declared 16384, so the host had to inspect the actual ELF. On API 37/fatal, the public quantization call returned `NATIVE_LIBRARY_PAGE_ALIGNMENT_UNSUPPORTED` with 4096/16384 in the message; the host did not crash. This was a current APK containing the genuine old library, not an untouched historical release APK. The current plugin was restored after the test.

## Additional fixes discovered during execution

- Paddle Lite's old arm64 `.dynsym sh_info` was corrected from 3 to 10 for modern LLD; every PT_LOAD byte was verified unchanged. The repository retains original/current hashes and a deterministic repair script.
- The dormant x86_64 OpenCV entries in all four Paddle AARs were 4 KB aligned even though those APKs currently ship ARM only. They now use the verified OpenCV donor, with per-entry provenance. If re-extracting the original Paddle v3 SDK, rerun the host's `refresh_paddle_opencv.py` to keep the unused SDK copy consistent.
- Paddle followed by Rapid in one process exposed duplicate static OpenMP runtimes (`__kmp_register_library_startup` / `__kmp_fatal`). Rapid now uses OpenCV 4.8.0's shared TBB runtime and Maven ORT 1.21.1. No duplicate-runtime override is used. New Rapid plugins require host build 5279; the host's optional native dependency handling preserves older Rapid APKs.
- The verified OpenCV r26b prebuilt and already aligned LuaLS executables retain their actual provenance. This deployment rebuilt the failing libraries with r28.2; LuaLS's explicit flags apply to its next rebuild.

## Remaining acceptance

A physical 16 KB arm64 device is still required, particularly for ARM-only Paddle and Yolo.
The remaining per-plugin functional matrix, later host/plugin CI publication, and D11 QuickJS-Host
rebase stay open in the roadmap. An APK install or ELF pass is not recorded as a runtime pass.
Bun's x86_64 JSC page-size assumption remains B1. Q1-Q4 used the roadmap's recommended
implementation defaults; they were not represented as new explicit user decisions.
