# Android SDK 37: P3.1 targetSdk 37 切换与自动化门禁 (2026-09-14)

## 1. 结果与范围

`version.properties` 的 `TARGET_SDK_VERSION` 36 -> 37, `TARGET_SDK_VERSION_INRT` 29 -> 37 (D2 / D3 的最后一步). 编译 SDK 与工具链不变 (compileSdk 37, AGP 9.4.0 / Gradle 9.7.1 / Kotlin 2.4.0). 本文记录依 Roadmap 第 0 节 (D19) 的自动化门禁结果: 构建 / 单测 / lint, 以及 `tools/sdk37/run_gate.py` 在 `AVD_API_37` (16 KB 镜像) 与五台旧系统真机上的执行. 原始日志、APK 与门禁报告位于 `build/sdk37-p3/` (不入库).

未包含: inrt 打包夹具 (P3.3)、Runtime Kit (P3.4)、远程 CI (P4)、真实 LAN / 可听性 / OEM 桌面 (RC-SMOKE / WATCH). 裸 inrt 模板没有 `assets/project/project.json`, 其 `SplashActivity` 必然 NPE, 因此门禁只核对其 badging / 安装 / 已安装 target, 启动步骤记 SKIP.

## 3. 门禁工具

`tools/sdk37/run_gate.py` (说明见 [工具 README](../../../tools/sdk37/README.md#one-command-gate)): 产物 badging / SHA-256 -> 安装 -> 已安装 target / debuggable / 测试包身份 -> 按设备自动选择的无人值守 instrumentation 套件 -> 模拟器专属步骤 -> JVM 汇总 -> `gate.json` / `gate.md`. 主机侧自检 `test_run_gate.py` 12 项通过. 开发过程中修正的事实:

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 测试包 badging 解析失败 | androidTest APK 的 `versionCode=''`; aapt2 输出 `minSdkVersion:` 而非 `sdkVersion:` | 解析放宽 |
| inrt 启动 "alive 但有 crash" | 裸模板无 `assets/project/project.json`, `SplashActivity.onCreate` NPE, 落到 CrashReportActivity | 无 project 时 SKIP; `--inrt-apk` 接受打包夹具; crash 检测改为按启动时间窗过滤 logcat |
| API 28 连续套件 "Process crashed" 0/4 | 上一次 instrumentation 的进程尚在退出, runner 进程未起即亡 (同一手机前一轮通过) | 套件间 3 秒沉降, 未跑任何测试即崩溃时重试一次; 重跑未触发重试 |
| 模拟器 a11y 冒烟卡在开头 | `am force-stop` 会禁用无障碍服务; instrumentation 杀进程后服务停留在系统 `Crashed services`, 设置不变则不重绑 | 准备步骤总是移除再加入服务并等待 `Bound services`; 不再 force-stop 后直接启动 |
| 冒烟无任何输出 | AutoJs6 `console` 是不可赋值的 augmentable proxy (`InternalError: Unknown key "log"`) | 包装脚本在函数作用域用局部 `console` 遮蔽后 `eval` 冒烟脚本 |
| 冒烟 28/42, 全部为 rootInActiveWindow 为 null | 重绑后系统在下一次窗口变化前不知道活动窗口 | 启动脚本前先把宿主主界面拉到前台 |
| 冒烟 42/42 却报 "no summary" | 冒烟脚本以 `\n` 开头打印汇总行 | 解析允许汇总行不带 `LOG ` 前缀 |
| `ui-overlay` 夹具 13/14, `ticks=1` | instrumentation 冷进程下 UI 模式 Activity 首个 tick 出现在 574 ms (独立运行约 320 ms), 固定 600 ms 窗口只剩一次 tick; 与三个 compat 开关无关 (逐一 disable 仍失败) | 夹具改为从首个 tick 起观察 600 ms, 5 秒内无 tick 才判失败, 并把 `firstTickAfterMs` 写入错误与 logcat |

## 5. 边界

- 模拟器 PASS 与真机无人值守套件通过不证明真实 LAN 拓扑、可听性、OEM 桌面 / 通知、人工 UI, 这些按 Roadmap 第 0.4 节 RC-SMOKE 或各条目的 WATCH 处理.
- inrt 只验证了模板的 badging / 安装 / 已安装 target; 带 `assets/project` 的 target 37 夹具与 `run_inrt_storage_probe.py` 矩阵留给 P3.3.
- `ui-overlay` 夹具的修改放宽了 "Activity 必须在 600 ms 内出现" 的隐含要求, 保留 "回调持续运行" 的本意; `firstTickAfterMs` 记入 logcat 供后续比较.
- 远程 CI 未推送验证 (P4).
