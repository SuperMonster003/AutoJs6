## 2. 实际问题与修改

迁移前主 Manifest 同时声明 `android:usesCleartextTraffic="true"` 和 NSC.
主 NSC 没有设置 `base-config.cleartextTrafficPermitted`, debug 覆盖文件却显式设置为 true.
Android 官方说明: API 24+ 存在 NSC 时忽略该 Manifest 开关; 此属性在 target 38+ 也将被忽略.
本项由 Q7 纳入, 不描述成 Android 17 强制移除旧属性.
[Manifest 说明](https://developer.android.com/guide/topics/manifest/application-element#usesCleartextTraffic).

修改后主 NSC 明确允许脚本自定义 HTTP 端点, 移除 Manifest 的旧开关. AutoJs6 的端点由脚本选择,
因此使用 `base-config cleartextTrafficPermitted="true"`, 不是固定少数域的清单.
`githubusercontent.com` 及其子域继续禁止 HTTP; 系统 CA 和该域的既有 ISRG Root X1 保持原状.
生产文件不加入 CT / ECH 配置或新信任锚; debug CA 继续只出现在既有的三个保留测试域.
配置继承和 base-config 的含义见 [官方 NSC 文档](https://developer.android.com/privacy-and-security/security-config).

这是一次有效行为修正: API 37 上旧 release 的普通 HTTP / Rhino 请求被拒绝, 新 release 成功.
API 24 上旧 release 已可访问 HTTP, 此次回归保持通过. 不把 API 37 的默认值差异推广到所有旧系统.

源码仅改主 Manifest 和主 / debug NSC, 没有公开 API 签名或运行时权限请求模型变化.
已检查关联文档的 HTTP 说明, 未发现需要修正的冲突描述; 不需要文档 / d.ts 生成或关联仓库版本递增.
宿主 6.8.0 的 `fix` 已更新 10 语言 JSON, 日期为 2026/09/14, 并运行 `.python/generate_markdown.py`.

## 4. TLS、CT 与 APK 边界

复用 `NetworkSecurityCompatibilityDeviceTest` 与 `tls_fixture.py`. 服务器只监听 PC
`127.0.0.1:17647`, 两台独占 AVD 各创建一条同端口 `adb reverse`, 客户端用 `127.0.0.1`
访问. 不申请本地网络权限, 不修改 compat, 不安装系统 / 用户 CA. 这条路径不是实际 LAN 验收.

| 系统 / 目标 | Debug 测试 | Release 测试 |
| --- | --- | --- |
| API 37, 正常宿主 36 / inrt 29 | 各 6/6 | 各 1/1, 私有 CA 默认拒绝 |
| API 37, 宿主 / inrt 覆盖 target 37 | 各 6/6 | 不构建覆盖 target 的发行包 |
| API 24, 正常宿主 36 / inrt 29 | 各 6/6 | 各 1/1, 私有 CA 默认拒绝 |

合计 **40/40**. Debug 六项继续验证未知 CA 拒绝、指定域信任、显式 CT 缺 SCT 拒绝
(API 24 不支持 CT, 保留旧系统成功分支)、默认 CT / ECH 策略, 以及两个 insecure 名称的
同步 / 回调 / Promise 请求隔离和主机名校验恢复. API 37 target 37 的默认 CT=true、ECH mode=2;
正常 target 的 CT=false、ECH mode=1. 所有 178 条 ClientHello 观测均未包含 ECH 扩展,
受控服务端不支持 ECH, 不把策略查询标为协商通过.

对 12 个应用 APK (迁移前 2、正常 4、覆盖 2、最终恢复 4) 读取实际编译后的 Manifest / NSC,
并检查 ZIP 内证书内容. 新包均无 Manifest 明文开关、主配置明确允许 HTTP、保留 GitHub HTTPS 限制.
所有 release 均无测试 CA 字节、无其资源定义、无测试域或额外 CT / ECH 配置.

三轮构建均成功: 正常 debug / release / 两份测试包 3 分 58 秒、target 37 debug / 测试包 18 秒、
恢复正常目标并纳入生成日志的 debug / release 16 秒. 原有 native page alignment 门禁随 assemble 执行.
最后输出与已测试的正常 APK 逐 ZIP entry 比较: 两个 inrt 完全相同, 两个宿主只有 11 个
`assets/doc/CHANGELOG*.md` 内容不同, DEX 和编译资源相同. 工具既有解析 / 夹具测试 **4/4**.
本次不另跑全量 Lint, 不宣称 R8 优化通过.
