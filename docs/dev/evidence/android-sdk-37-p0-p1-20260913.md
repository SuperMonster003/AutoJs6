## 2. P0.2: 临时 target 与 compat 工具

`Versions.kt` 读取 `autojs.sdk.target.override`, 接受 minSdk 至 max(compileSdk, 37) 范围内的整数, 允许最初 compile 36 / target 37 的探针. 无属性时读取各 flavor 原有 target. 覆盖提示会打印到构建日志, 不回写版本文件.

`VersionsPlugin` 在实际 release 任务以及 Runtime Kit / 模板分发任务上挂接 `SdkTargetOverrideGuard`. guard 无输出缓存, 执行即拒绝; 因而已有 up-to-date 产物、任务缩写、聚合入口都不会绕过. 使用任务依赖也避免依赖只在配置阶段触发的 task graph 回调. 参见 [Gradle TaskExecutionGraph](https://docs.gradle.org/current/javadoc/org/gradle/api/execution/TaskExecutionGraph.html). 本次未宣称整个工程已兼容 configuration cache.

```powershell
./gradlew '-Pautojs.sdk.target.override=37' :app:assembleAppDebug :app:assembleInrtDebug
```

覆盖构建成功, 6m 47s, 782 tasks / 291 executed. app 与 inrt 的 universal debug APK 均为 compile 37 / target 37 / min 24, 已安装 API 37 并以 `dumpsys package` 再核对. 此命令直接请求 inrt assemble, 现有 ABI splits 逻辑因此只产出 universal, 不将其记为完整 ABI 矩阵.

| target 37 inrt debug universal | `6bc0c1bbff95923deeabac32c4444c7597dca5de2fb0c25a6b400789603fac8d` |

以下 11 项均产生预期拒绝, 见 `override-checks.json` 与其逐项日志:

| 类型 | 参数 / 任务 |
| --- | --- |
| 非法 target | `abc`, `23`, `38` |
| 非法 lint 属性 | `-Pautojs.sdk.lint.verify=invalid` |
| 带 target 37 覆盖的 release | `:app:assembleAppRelease`, `:app:assembleInrtRelease`, 缩写 `:app:assAppRel` |

模板任务属于根项目. 最初误用 `:app:assembleApkBuilderTemplateDistribution` 的 task-not-found 结果不算 guard 通过, 随后以根任务重新验证. 最后一次拒绝前后, 既有 app / inrt release x86_64 APK hash 不变, 见 `guard-artifact-hashes.json`.

[compat.sh](../../../tools/sdk37/compat.sh) 先验证设备、安装包的 DEBUGGABLE 与整批 change, 再逐个执行 `am compat`; 每批保存原状态、命令结果与最终状态. 在 API 37 上对 `USE_NEW_MESSAGEQUEUE` (421623328) / `LOOPER_CLEARS_THREAD_INTERRUPTED` (458413887) 执行 enable / reset, 恢复后对应 dump 行与初始一致. 非法第二个 change 在第一个变更前就被拒绝; release APK 同样在修改前被拒绝.

`reset` 仅恢复平台默认值. 原先已有显式 override 时, 应按快照恢复原 enable / disable, 不把 reset 当作通用回滚. [dump_compat.sh](../../../tools/sdk37/dump_compat.sh) 拒绝覆盖既有证据目录. 音频 / 内存控制只在 [工具说明](../../../tools/sdk37/README.md) 单列, 本次未修改这些设备级状态.

## 3. 有效 lint 基线与差异

`-Pautojs.sdk.lint.verify=true` 启用原先关闭的 app / inrt vital analysis, 同时绕过模板分发的 app vital 跳过条件, `abortOnError=true`. 未传此属性的普通构建保持原行为. 不将普通 assemble 中的 SKIPPED 任务当作 lint 通过.

先在 compile 36 生成基线, 再在 37 生成候选报告, 使用相同工具链 / lint 配置. 两轮均执行:

```powershell
./gradlew --offline --continue --console=plain --max-workers=2 `
  '-Dorg.gradle.jvmargs=-Xmx12g -XX:+UseG1GC -Dfile.encoding=UTF-8' `
  '-Pkotlin.daemon.jvmargs=-Xmx6g' '-Pautojs.sdk.lint.verify=true' `
  :app:lintAppDebug :app:lintVitalAppRelease :app:lintVitalInrtRelease
```

SDK 37 那一轮同时请求 `:app:compileAppDebugAndroidTestKotlin`, 以复编 AndroidTest 的输入法 flag 修正; 该任务通过. SDK 36 首次使用默认 4 GB Gradle heap 时长时间 GC, 只停止本次 Gradle 客户端并重试; 12 GB / 2 workers 的完整分析完成. 基线重试耗时 21m 11s, 候选耗时 11m 47s. 这些内存选项仅用于命令, 没有修改项目 Gradle 默认配置.

| 报告 | SDK 36 | SDK 37 | 新增 / 减少 |
| --- | --- | --- | --- |
| appDebug XML | 546 Error + 1 Fatal, 2437 Warning, 3 Hint | 完全相同 | 0 / 0 |
| appRelease vital text | 1 Fatal | 相同 | 0 / 0 |
| inrtRelease vital text | 1 Fatal | 相同 | 0 / 0 |

SDK 36 与 37 的 debug Error / Fatal 分类均为:

| Issue ID | 数量 |
| --- | --- |
| MissingTranslation | 470 |
| NewApi | 61 |
| AppCompatCustomView | 6 |
| WrongConstant | 4 |
| MissingPermission | 2 |
| MissingSuperCall | 1 |
| GestureBackNavigation | 1 |
| RestrictedApi | 1 |
| RemoveWorkManagerInitializer (Fatal) | 1 |

两个 release 的 Fatal 都是既有 `RemoveWorkManagerInitializer`: Application 提供 WorkManager Configuration.Provider, 默认初始化器仍在 manifest 中. 本次未借 SDK 升级修改其初始化语义, 也未 suppress 此项. 新增 Error / Fatal / Warning 为零; 现有 61 个 NewApi 仍需按原问题处理.

AGP 9.4 的 vital 任务产生 text, 不是 debug XML. 原路径为 `app/build/intermediates/lint_vital_intermediate_text_report/<variant>/lintVitalReport<Variant>/lint-results-<variant>.txt`; 归档时分别改名为 `lint-results-vital-appRelease.txt` / `lint-results-vital-inrtRelease.txt`. debug XML / HTML / text / SARIF、版本文件、命令日志与 lint module 一并归档. model 明确分别使用 `android-36` / `android-37.0`, 两者 `abortOnError=true`, 无新增 disabled issue.

```powershell
python tools/sdk37/compare_lint.py build/sdk37-lint-36 build/sdk37-lint-37 `
  --output build/sdk37-p0-p1/lint-diff.json
```

比较退出 0. 工具按 ID / 严重性 / 消息 / 文件匹配并保留重复计数, 忽略行号移动. vital Error 行按其 fatal-only 任务语义记为 Fatal, 同时核对报告末尾数量避免漏解析. 人工构造的行号移动通过, 新增重复 Error 退出 1, 未解析 vital 诊断和缺报告退出 2. Python 语法检查通过. 完整报告仍显示原错误, 不新增 lint baseline 或忽略规则.

## 4. 构建、测试、产物与本地 CI

正常构建使用持久 target 36 / 29:

```powershell
./gradlew --offline --continue --console=plain --max-workers=4 `
  '-Dorg.gradle.jvmargs=-Xmx12g -XX:+UseG1GC -Dfile.encoding=UTF-8' `
  '-Pkotlin.daemon.jvmargs=-Xmx6g' `
  :app:assembleAppDebug :app:assembleAppRelease :app:generateRuntimeKit `
  :assembleApkBuilderTemplateDistribution :app:verifyNativePageAlignment `
  :app:testAppDebugUnitTest testDebugUnitTest :app:compileAppDebugAndroidTestKotlin
```

成功, 9m 57s, 2684 tasks / 862 executed, 见 `build-test-37.log`. Kit 的依赖构建了 inrt release, 模板插件 release 也已出包. 随后独立执行 `:app:assembleInrtDebug`, 成功 15s, 736 tasks / 7 executed, 见 `build-inrt-debug-normal-37.log`. 后者检查 target 29, 替换了此前输出目录中的 target 37 探针包; 探针已另存 `target37-debug/`.

不要把直接 `assembleInrt*` 和 Kit / 模板分发拼在同一命令中: 现有脚本会因显式 inrt assemble 请求全局关闭 ABI splits, 而 Kit 需要 5 种 ABI / universal 输出. 通过 Kit 的依赖构建 inrt release, 独立请求 inrt debug, 可覆盖两种场景.

| 正常产物 | 数量 | compile / target / min |
| --- | --- | --- |
| app debug | 5 (arm64-v8a / armeabi-v7a / x86 / x86_64 / universal) | 37 / 36 / 24 |
| app release | 5 | 37 / 36 / 24 |
| inrt release | 5 | 37 / 29 / 24 |
| inrt debug | 1 (universal) | 37 / 29 / 24 |
| Runtime Kit ZIP | 5 | 内部 template.apk = compile 37 / target 29 的 inrt release |

`apk-artifacts.json` 保存 16 个正常 APK 的 badging 结果、大小与 hash; `runtime-kit-artifacts.json` 保存 5 个 ZIP 及内部 template hash. 每份 template.apk 的 SHA-256 与对应已检查 inrt release 相同. release APK 均非 debuggable; 当前源码 `isMinifyEnabled=false`, debug 也继承此值, 因此没有 R8 优化验证结论.

16 KB Gradle 门禁的 AppDebug / AppRelease / InrtRelease 均 5 个 APK, 每组 24 个受检 arm64 / x86_64 native 条目, 失败为 0; InrtDebug universal 的 12 个条目也通过. 再以 CI 使用的 `tools/16kb/verify_apks.py` 检查 APK 输出目录及 Runtime Kit 展开目录均通过, 报告为 `ci-apk-alignment.json` / `ci-kit-alignment.json`. 输出目录内另有已有 AndroidTest APK, 不把它算入上述 16 个正常产物.

单元测试从本轮所执行任务的 JUnit XML 统计, 见 `unit-tests.json`:

- 总计 3166: 3161 通过, 5 跳过, 0 failures, 0 errors.
- app 2538: 2533 通过, 5 跳过; 不把编译 AndroidTest 当作运行全部 instrumentation tests.
- 47 个被选择任务: 26 个具有测试 XML, 21 个 NO-SOURCE. 对照 `settings.gradle.kts` 的 10 modules / 29 plugin-api / 1 plugins / 6 test-apps, 无遗漏, 见 `unit-coverage.json`. 本轮范围不包含外部 42 仓的测试, 也不称 NO-SOURCE 为用例通过.

CI 的 editor gate 原来固定查找 `const val VERSION = 1`, 但当前契约为 5, 在 SDK 修改前即失败. 最小修正为检查正整数 VERSION, 同时保持 MIN_SUPPORTED_VERSION=1 与 MAX_SUPPORTED_VERSION=VERSION. 当前 `node tools/ace-ci/check-ace-editor-gate.mjs` 通过; 无效版本 0、丢失 v1 支持、无界 MAX 的内存夹具均被拒绝. 其它 gate 断言保持.

CI 额外的 `:plugin-api:lua-runtime-api:assembleDebug` 及 ai-provider / dex-compiler / lua-runtime conformance 三个 assembleDebug 成功, 19s, 235 tasks / 50 executed, 见 `ci-local-assemblies.log`. 主构建已覆盖 CI 测试子集、AndroidTest 编译、Kit 与模板, 本地 native 脚本也已通过. 本机 Windows 结果不能证明 Ubuntu runner 的 SDK 自动下载、缓存或权限配置; `android.yml` 的远程结果仍待推送后记录.

`release-runtime-kit.yml` 会创建 / 更新 GitHub Release 资产并 dispatch 插件仓库, 本次只验证其本地构建与 native 检查, 未执行外部发布. 发布工作流随正常发布补验.
