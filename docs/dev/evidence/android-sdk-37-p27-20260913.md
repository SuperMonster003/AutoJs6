# Android SDK 37 P2.7: Parcel 与插件 IPC

日期: 2026-09-13. 会话起点 `4422786ab`, 测试与工具提交 `a6d037516`. [机器结果](android-sdk-37-p27-results-20260913.json) 保存实际 APK SHA-256、每组测试方法、有效兼容状态、原始记录哈希、失败探索和源码哈希. 原始 APK / 日志保留在宿主的忽略目录 `build/sdk37-p27/`.

本轮完成 P2.7 的本地自动化验证: 宿主 target 36 强制开启与 target 37 默认开启下, 11 个指定插件各有一条真实最短链路通过; 现有 Parcel / Bundle / extras 和插件元数据读取通过. 所测路径未发现需要修改生产序列化代码的 SDK 37 回归. 正常配置仍为 compile 37 / host target 36 / inrt target 29.

这不关闭真实 Tasker / 桌面操作、其它 ABI / OEM、inrt 成品 APK 或 P5 的全部 42 个插件发布验收. 插件本轮仍为 target 36, 分别开启自身的兼容开关.

## 1. 门控与负例

DEVICE-37: 镜像提供 `PARCEL_HARDENING` (416031865), `enableSinceTargetSdk=37`. 从该设备拉取的 `/system/framework/framework.jar` 的 `classes3.dex` 中, `Parcel.readValue` 对带长度前缀的值比较实际读取字节数与声明长度; 抛错分支同时要求 `failOnParcelSizeMismatch()` 和 `CompatChanges.isChangeEnabled(416031865L)` 为真. framework.jar SHA-256:

```text
cfd8c422620cf584b5f190d8e5a211b83468a5ffd2bdb5cad1e0e410a22f30d8
```

负例 `UnderReadingParcelable` 写两个整数, CREATOR 仅读第一个. 在 `Parcel.writeValue/readValue` 路径中, 该值的声明 payload 为 108 字节, 实际消费 104 字节. 测试同时在宿主和私有 `:sdk37_parcel_probe` 进程执行, 明确断言不同 PID 和相同实际 target:

| 条件 | 宿主负例 | 独立接收进程负例 | 正常数据 |
| --- | --- | --- | --- |
| target 36, 显式 disable | 不抛异常 | 不抛异常 | 往返完整 |
| target 36, 显式 enable | BadParcelableException, `consumed 104 bytes, but 108 expected. [throwing]` | 同左 | 往返完整 |
| target 37, reset 后默认 | 同上 | 同上 | 往返完整 |

这界定的是所测镜像的长度前缀读取检查. 不把它等同于所有 typed AIDL / native Binder 读取或 Parcel.recycle 后访问检查. 本机 SDK 36.1 源码已包含长度比较及平台 feature flag, 因此不能仅凭出现 BadParcelableException 就判定是 target 37 的新行为.

官方目标版本页与全体应用页本次未给出上述门控的完整定义; 兼容变更专题 URL 返回 404, 单独 Parcel 专题多次不可用. [Android 17 目标版本变更](https://developer.android.com/about/versions/17/behavior-changes-17)、[全体应用变更](https://developer.android.com/about/versions/17/behavior-changes-all)、[AOSP main Parcel](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/main/core/java/android/os/Parcel.java) 只作为背景链接, 不用 main 分支代替该镜像实现. 本节结论依据设备字节码与正反例, 未推定其它 QPR 镜像的行为或生产 opt-out 期限.

## 4. 宿主数据边界

- `ExecutionConfig`: 显式写入中文 workingDirectory、路径数组、flags、delay、interval、loopTimes; 检查 CREATOR 恰好消费现有六字段长度, 后续 sentinel 未被吞读, 再跨独立进程核对值. 现有协议没有序列化 scriptConfig / arguments, 本轮没有扩展协议或改动冻结的 `com/stardust` 包.
- `PluginInfo`: null 与完整字段两组, 覆盖长整型 versionCode、字符串数组、嵌套 Bundle、布尔值和 int 数组; 接收进程强制反序列化后返回, 逐字段比较.
- Tasker: 按现有 ScriptIntents JSON 形状构造中文路径与前置脚本, 经过跨进程 Intent / Bundle 后再校验 JSON 及内容. 未调用真正的 Tasker 配置 / 保存 / 触发 UI.
- 快捷方式: 使用生产 `ScriptShortcutIntentFactory` 生成 Lua 描述, 跨进程后对所有 extras 比较并校验 engine / path. 未操作桌面 launcher.
- `InstalledPluginRepository`: 分别走 package-manager snapshot 与完整发现, 11 个指定插件均存在、无 bindError, 实际日志均为 `info=true`; 汇总器进一步核对日志版本等于所装 APK 版本. 通用 PluginInfo 的字段往返不替代各插件完整能力协商验收.

## 5. 失败探索与处理

| 观察 | 对照与判断 | 处理 |
| --- | --- | --- |
| 初版 QuickJS 测试没有匹配控制台内容 | enable / disable 都失败, 设备日志已有准确标记; 初版按整个带换行的文本末尾判断 | 按文本行匹配. 最终 enable / disable / target 37 默认均通过, 未改生产 QuickJS 引擎 |
| 旧 Python R2 诊断返回 `INVALID_REQUEST/SESSION_OPEN` | enable / disable 一致; 源码分析显示该诊断协商新协议后仍走不带 host broker 的旧 openSession, provider 的 1.5+ 分支要求 broker; 没有取得调试器中的协商值 | 本轮使用当前生产 PythonPluginScriptEngine 建立最短链路. 原诊断未被删除或标为通过, 后续需按它自己的协议验收范围维护 |
| 初版新的 Python 测试把结果强转为旧 wire 类型 | 实际类型为 `PythonRuntimeExecutionResult`, 设备已输出预期 CPython 文本 | 改为读取当前宿主包装对象的 terminal; 最终三个条件均通过 |
| 早期日志收集使用 `Parcel:A` | logcat 返回 Invalid filter expression; instrumentation 本身已完成 | 改为 `Parcel:F`, 记录日志命令状态及设备时间起点. 保留原失败日志; 后续 target 37 全矩阵与最终关闭对照有有效日志 |
| IDE Remote JVM 调试会话立即停止 | instrumentation 报 Process crashed, DRAIN_EVENTS 无可用 session; 没有 logpoint 值 | 明确记录调试器不可用, 改用无调试器的黑盒对照、既有日志和邻近源码. 临时 run config / 端口转发 / 两个 agent 断点已移除, 五个用户断点保持原状态 |

运行时诊断按本机会话的 `ij-debugger` 技能尝试; 没有取得调试器证据, 所以不把本轮日志或源码推断标作 debugger 结论. 私有 ADB 与测试 APK 签名处理属于实验环境准备, 不代表生产升级或发布验收.

## 6. 复跑与后续门禁

完整命令、插件 applicationId、前置夹具和预期见 [Parcel 工具说明](../../../tools/sdk37/README.md#parcel-and-plugin-ipc). 默认每次输出新目录, 不接受跳过、缺失方法或仅有 `OK (n tests)` 的不完整报告. 工具同时检查宿主及各被测插件的有效 compat 状态, 不能只对宿主启用后声称插件已覆盖.

- 正常 appDebug / androidTest 与 target 37 覆盖构建通过; 最后重新构建并安装正常 target 36 产物完成对照. 各次 assemble 的原生 16 KB 对齐检查通过, 这仍不等于 16 KB 内核设备测试.
- appRelease 合并 manifest 检查通过, 没有 Parcel debug service. 本轮未重跑 release 全量出包或远程 CI.
- Python gate parser 4/4, 既有 evidence parser / LAN fixture 4/4; checklist 导出仍为 99 行 NOT_RUN, 没有用 AVD 结果自动勾选实体机清单.
- 本轮无生产 API / SDK 配置 / Gradle 依赖 / 插件源码变更, 因而不新增产品 changelog, 不触发文档站或 d.ts 发布流程.
- 结束前清除了测试包的 PARCEL_HARDENING 覆盖, 关闭本轮只读 AVD 和独立 ADB 5049; 基础 AVD 数据未保存. 共享 ADB 5037 的异常没有在本轮修复.

仍需维护者提供或执行: Android 17 真机及实际 launcher / Tasker 操作; 真实 16 KB 内核 / arm64 及 OEM 回归; Lua 正式候选发布产物和其它插件的 P5 逐仓验证. 具体步骤和预期继续由 [IPC01 与各 PL 行](../android-sdk-37-physical-device-tests.md) 管理. 本轮不需要新的功能取舍; 后续可继续 P2.8 的存储行为门控验证.
