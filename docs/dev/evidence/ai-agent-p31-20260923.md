# P3.1 host script-directory settings evidence

Date: 2026-09-23. Host: AutoJs6 6.8.0 / 5286. Companion: AI Agent
1.0.0 / 26. Scope is the original P3.1 catalog presentation and root settings.
The public ai.agent API, parameter completion and script execution adapters
remain in their original P5 and P3.2/P3.3 stages.

## Host changes

- The authenticated attachment broadcast and foreground fallback accept an
  optional root-only linkConfigJson proposal. The PendingIntent creator, installed
  UID, signer, plugin enablement and authorization checks remain in force.
- Parsing rejects authority fields, duplicate keys/paths, relative paths,
  traversal, controls, oversized JSON and more than 32 additional directories.
  Existing catalog validation still checks actual directories, canonical paths,
  user-visible storage and working-directory ancestry before accepting anything.
- Applying settings preserves the host locale and grantSummary. Failed validation
  or a rejected plugin update leaves the accepted configuration in place. Only
  accepted settings persist across reconnect; changing settings never starts a
  task. The broker accepts one working-directory selector plus 32 extra roots.
- Build 5286 is now the minimum Agent host because older builds ignore the root
  proposal. No AIDL transactions or public script APIs change. The three release
  API artifacts were assembled together for staging in the plugin repository.
- Protocol documentation and all 10 changelog languages describe the current
  behavior. Historical P1/P2 evidence retains its original build numbers.

## Findings and limits

The root persistence test initially compared raw org.json and Gson strings;
Android's slash escaping made equal JSON compare unequal. It now compares the
host-normalized representation. The final device runs above include this fix.

Two whole-suite runs exposed an unrelated existing MailWatchRunnerTest race.
The runner sets its finished flag before delivering the close event, while the
test waited for the flag and immediately asserted the event list. The isolated
mail suite passed, but the race recurred under the full suite. A separate test-only
commit now waits for close delivery and still asserts the finished flag and full
event order. No mail production behavior changed; the final whole suite passed.

This is E1/E2 evidence with a scripted model broker and real host catalog/Binder
transport. No production model task, script invocation, E4 acceptance, physical
device matrix, complete host lint or host release/R8 build was performed here.
The standalone conformance APK and remaining roadmap gates retain their scope.
