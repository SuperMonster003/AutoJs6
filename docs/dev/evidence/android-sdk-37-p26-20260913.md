# SDK 37 P2.6: TLS 信任, CT, ECH 与 HTTP 请求隔离

日期: 2026-09-13. 源码基线: 宿主 `0dc692885`, 工作区开始时干净.
本轮完成 P2.6 的受控网络对照和一个实际 HTTP 修复, 不关闭企业代理 / 真实 ECH 验收.
正常版本输入保持 compileSdk 37 / 宿主 targetSdk 36 / inrt targetSdk 29.

## 1. 实际修复

旧实现从当前脚本共享的 OkHttpClient 复制 Builder, 应用 `isInsecure` / `insecure`
后调用 `muteClient(builder)`. 放行所有证书与主机名的客户端因此成为后续请求的基础.
未传此选项或传入 false 都不会恢复原校验.

修复前, 真实 Rhino 测试顺序如下:

1. 默认请求 `untrusted.sdk37.test`: 证书链拒绝.
2. 显式 insecure 请求: HTTP 200, 固定响应体正确.
3. 再次默认请求: 仍返回 HTTP 200, 两个选项名均复现.

修复将常规 `timeout` / `client` 配置先保存到共享客户端, 仅在本次请求的
Builder 上施加 TLS 豁免, 返回本次 OkHttpClient 交给 `prepareRequest` 创建 Call.
同步, 传统回调和 Promise 都经过同一准备路径. 共享配置中的显式自定义
TrustManager / HostnameVerifier 不会被擅自重置为系统默认值.

修改文件:

- `app/src/main/java/org/autojs/autojs/runtime/api/augment/http/RequestBuilder.kt`
- `app/src/main/java/org/autojs/autojs/runtime/api/augment/http/Http.kt`

这是既有 HTTP 行为缺陷, 不是仅在 target 37 下发生的新平台限制.
修复无需等待最终 target 切换, 已计入 6.8.0 的 10 语言 `fix` 日志.

CertificateException: Certificate chain does not conform to required transparency policy: NOT_ENOUGH_SCTS

## 4. ECH 与文档版本边界

VERIFIED: [Network Security Configuration](https://developer.android.com/privacy-and-security/security-config)
说明系统 CA 默认信任、用户 / 资源 CA 的 CT 默认豁免以及显式 CT 配置.
CA 必须先纳入信任锚; 默认宿主并不信任任意用户安装的 CA.

VERIFIED: [NetworkSecurityPolicy API](https://developer.android.com/reference/android/security/NetworkSecurityPolicy)
已包含 37.2 新增的模式和 OPPORTUNISTIC 弃用信息. 本机 compile 平台和运行镜像是
37.0: UNKNOWN=0, DISABLED=1, OPPORTUNISTIC=2, ENABLED=3. 初次测试按
较新说明将默认值预期为 3, 实测为 2, 该失败保留. 最终改为显式数字模式参数,
并用 target / compat 的独立对照确认 1 与 2 的变化, 未调用 37.2 API.

DEVICE-37: `trusted.sdk37.test` 与 `raw.githubusercontent.com` 的默认 CT 查询均为 false;
`localhost` 也为 false. 前者有受控真实连接, 后两者仅做策略查询.
本轮没有记录 `raw.githubusercontent.com` 的真实公网证书链, 因此不宣称它的
实际连接采用了某条链或已通过 CT.

SOURCE + WIRE: 当前 OkHttp 4.12.0 源码归档未发现 `setEchConfigList`,
`getDomainEncryptionMode` 或 `EchConfigList` 调用. 当前 fixture 的 ClientHello
未出现 `0xfe0d`, 且服务器能读到 SNI. 这仅证明这些连接未使用 ECH;
不是对全部网络库、连接类型或未来 WebView 版本的判断.
本夹具不支持 ECH, 即使看到扩展也可能是 GREASE, 不能作为成功协商证据.

Q2 / D13 因此沿用生产默认配置. 没有证据支持为任意真实域增加 CT 例外,
也没有为测试改用新的 OkHttp 版本.
