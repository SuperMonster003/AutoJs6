# AI Agent P1.4 host evidence (2026-09-23)

This records the host bridge, script registration and execution-result work in
AI Agent roadmap P1.4. It does not claim completion of P1 as a whole, the plugin
Agent loop, or the public JavaScript `ai.agent` API.

## Delivered behavior

- `accessibility.dump` supports compact text compatible with the existing MCP
  formatter. Each capability provider owns up to eight LRU snapshots. Actions
  re-resolve `nodeRef` against the current tree and reject stale, ambiguous or
  foreign references with `invalid-request` / `NODE_REF_STALE`.
- `accessibility.readScreenText` combines accessibility screenshot capture,
  fallback to an already-authorized MediaProjection session, and the existing
  automatic OCR provider selection. Responses contain at most 400 text entries
  and 64 KiB. Missing enabled OCR returns `unavailable` / `OCR_PLUGIN_REQUIRED`.
  Capture, crop and late-result bitmap cleanup belong to the host operation.
- `agent.listScripts`, `readManifest` and `execRegistered` use project manifests
  or leading `@agent` comments. The catalog enforces canonical approved roots,
  bounded scanning, scalar argument schemas and cache invalidation. A narrowed
  request root cannot authorize a new directory. Configuration replaces the
  approved additional roots; omission clears them, including after reattach.
- `ProjectConfig` retains the optional `agent` object without opting ordinary
  projects in or inserting an invalid empty ID when saving a default ID.
- Registered execution uses the existing launch factory and main-process
  dispatch service, validates the actual source against the authorized entry,
  passes parameters and separate Agent context, waits for completion, and stops
  owned execution on deadline or provider destruction. Results are valid JSON
  within 64 KiB. Console fallback is bounded and marked `global-window`.
- Provider destruction prevents late first-time creation of OCR or Agent
  helpers. Prepared root updates cannot commit after destruction.

Protocol details are in [AI Agent protocol](../ai-agent-protocol-v1.md),
[script manifest format](../agent-script-manifest-v1.md), and
[execution test notes](../agent-script-execution-testing.md).

## Problems caught before completion

- A ProjectConfig compatibility check initially ran in plain JVM tests, where
  its existing LaunchConfig constructor has no Android application context.
  Actual FuzzyGson/save checks now run on Android; plain model serialization
  remains covered by JVM tests.
- Android ICU rejected the original parameter/result regex's unescaped closing
  delimiters although desktop JVM regex accepted them. A small D8/app_process
  experiment reproduced the failure; explicit escapes and an Android parser
  regression fixed the three affected execution cases. The temporary device
  experiment file was removed.
- Review corrected nested directories named `agent`, overlapping configured
  scan roots, and project main aliases to match the existing FuzzyDeserializer.
- Review corrected duplicate synchronous replies, cancellation before service
  start, actual project-entry replacement, helper initialization after provider
  destruction, and configuration-root behavior across reattachment.

## Acceptance boundaries

Public `ai.agent.result/context`, ordinary-script warning behavior and the public
JavaScript acceptance fixture remain P5. These device tests use the internal
execution-state Java hooks; the P1.4 combined test checklist therefore retains
its pending public-API portion.

Successful OCR recognition/crop/cleanup tests inject a recognizer and bitmap;
they do not establish a real screenshot-to-installed-OCR success matrix or
MediaProjection consent/fallback on every Android version. The missing-OCR case
uses the actual provider. The existing host-to-external-OCR image transport is
retained: no image is sent to Agent, while the OCR service necessarily receives
its input. This clarifies the roadmap's bitmap ownership wording.

The real execution fixture uses Rhino. Other launch engines, physical-device
compatibility, model calls, release/R8 validation and the independent P7 fake
Agent APK matrix are outside this check. P1.5/P1.6 keep their existing place in
the roadmap. MCP's future compact/nodeRef migration is recorded in its own
roadmap; its runtime and v1 AAR were not migrated here.
