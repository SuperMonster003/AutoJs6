# Candidate feature schema 2

`CandidateFeatures` is the only feature implementation, shared by dataset export and host inference. It takes the capture-state request and the complete verified candidate group. It never reads later snapshots, mutation names, labels, dataset splits, application names used as dataset metadata, or truth keys. `FeatureSchema.names` fixes the 75 columns in roadmap E.3 order. `namesHash` (`a2b899bcc46125ba`) is the first 16 lowercase hexadecimal characters of SHA-256 over the UTF-8 names joined by `\n`, without a final newline.

Any change to a name, order, aggregation, heuristic, or numerical encoding requires a new `featureSchemaVersion` and updated fixture snapshots. The three fixture snapshots are hand-derived expected values, not regenerated from the extractor during tests.

Schema 2 (2026-10-09) adds the `SELF_RELATIVE` family: one more family flag, the eight `relative_*` selector fields and `relative_match_count` / `relative_match_ratio`. Every schema 1 name keeps its value, so schema 1 (64 columns, `9c6a5d8279ffca0e`) is the by-name projection `FeatureSchema.project(vector, 1)`. The host still loads schema 1 packages and ranks with projected vectors, but a schema 1 model is unavailable (`INCOMPATIBLE_FEATURES`) for any candidate group containing a family it has not seen. `v2-vectors.json` was derived from the schema 1 snapshot by column name; `v1-vectors.json` remains the projection reference.

## API and capture boundary

`CandidateFeatures.extract(request, candidate, group)` handles a complete detached capture whose root has no parent. For repeated extraction, use `CandidateFeatures.prepare(request, group, verifier.tree)`, then `extract(candidate)` or `extractAll()`. Passing the verifier's `NodeTree` retains the exact capture boundary, including a captured subtree whose original source has a parent. `extractAll()` preserves input group order; feature values do not depend on that order or on the order of request targets.

The group must contain unique `planKey` values and candidates resolving to the same target set. Rule ordering uses the unchanged `RuleRanker`, including its `planKey` tie break. Tree indexing, full subtree structure signatures, id statistics, and target statistics are computed once per prepared group. Signature interning is iterative and stores child signature integers, so a 5,000-node chain does not require recursion or quadratic signature strings. No nodes are mutated or recycled.

## Shared encoding

- Every value is a finite `Float`. An unavailable value is `-1`; an available Boolean is exactly `0` or `1`.
- Nonnegative counts, lengths, distances, magnitudes, and the within-family ordinal use `ln(1 + x)`. Ratios are untransformed. `rule_cost_gap` is an untransformed nonnegative difference in rule cost units.
- Target sets are deduplicated. For collection requests, target Boolean fields use **all**: the flag is `1` only when every target has the property. Depth and same-class sibling counts use the arithmetic mean **before** applying `ln(1 + x)`. Missing class names are excluded from the sibling mean; if every class name is missing, the result is `-1`.
- Strings are measured in Unicode code points, including supplementary characters. Aggregate ratios count matching code points divided by all code points in the distinct literals. An explicitly present empty string has length and ratios `0`; absence of a literal has value `-1`.

## Columns

| Group | Exact encoding |
| --- | --- |
| Request | `scope_collection`; six action flags in sealed declaration order `none`, `click`, `long_click`, `set_text`, `scroll_forward`, `scroll_backward`; attribute flags in `Attr` enum order `id`, `text`, `desc`. Query mode, timeout, output style, receiver preference and set-text payload are not additional features. Actual receiver ascent is captured below. |
| Family | Six flags in `LocatePlan.Family` enum order: `self`, `self_index`, `anchor_path`, `anchor_search`, `container_items`, `self_relative`. `receiver_up_levels` is the verified actual ascent, with zero for self. |
| Selectors | Eight fields for `self_`, eight for `anchor_`, then eight for `relative_`: condition count; full-id, entry-id, text, description, class, package presence; structural condition count. SELF/SELF_INDEX/SELF_RELATIVE have a self selector and no anchor. ANCHOR_PATH has an anchor and no self selector. ANCHOR_SEARCH/CONTAINER_ITEMS use the nested search as self and the entry selector as anchor. Only SELF_RELATIVE has a relative selector (its final `Match` step). A nonexistent selector contributes eight `-1` values; an existing empty selector contributes eight zeros. Id flags concern literal `id` conditions; text/description flags cover names starting with `text`/`desc`; class/package flags concern `className`/`packageName`. Structural classification uses `RuleRanker.isStructural` unchanged; the first-line prefixes `textStartsWith`/`descStartsWith` (D24) count as text/description, not as structural conditions, so schema 2 keeps its names and encoding. |
| Id quality | Across both selectors' distinct `id` literals: entry length is the maximum length after stripping `:id/`; obfuscation is `any` entry with at most two code points or an ASCII alphanumeric entry of at least three characters containing a letter and no `a/e/i/o/u` (case insensitive). This is a fixed heuristic, so abbreviations such as `btn` also match. Cross-package duplication is `any` entry present under more than one resource namespace in the capture, even if this candidate uses a full id. A non-resource id falls back to the node's package; an unknown namespace is not counted as another package. No id literal means all three values are `-1`. |
| Text quality | Maximum distinct text literal length, digit ratio, dynamic flag, CJK ratio; maximum distinct description literal length and dynamic flag. Literals come from every selector of the plan (entry, nested search and relative match), with names starting with `text`/`desc`. Dynamic means the verifier's flag or any Unicode digit in a literal, covering numeric/time/count forms. CJK covers Unicode ranges `3400..4DBF`, `4E00..9FFF`, `F900..FAFF`, `20000..2EE5F`, `2F800..2FA1F`, `30000..323AF`. Dynamic flags use `any`; unavailable literal fields are `-1`. |
| Index | `index_abs = ln(1 + abs(literal index))`, using `Long` before absolute value; `index_negative` tests the literal sign. Thus `-1` has magnitude `1`, not edge distance `0`. `index_rel` is the resolved nonnegative index divided by the complete selector match count. All three are `-1` without an Index step. `selector_match_count` is the verifier's full match count, even when script semantics take only the first. `relative_match_count` is `ln(1 + kept entries)` and `relative_match_ratio` is kept entries divided by the full match count, both only for SELF_RELATIVE and `-1` otherwise. |
| Path | Verified navigation-step, up-level, child-step, sibling-step and maximum absolute child-index/sibling-offset counts, covering ANCHOR_PATH paths and SELF_RELATIVE relations. `anchor_distance` is `-1` for SELF/SELF_INDEX/SELF_RELATIVE; otherwise it is the verified tree edge distance. For CONTAINER_ITEMS it is the mean anchor-to-target distance before the logarithm, independent of which collection member came first. |
| Container | Available only for CONTAINER_ITEMS: `container_item_count` is the verified number of selected items; uniformity is the largest equal-subtree-signature subset divided by all distinct selected items. A signature contains class name, full id, and the ordered child signatures, ignoring text, descriptions, Boolean state and bounds. Both fields are `-1` for other families. |
| Target | Depth counts edges from the capture root. Id/text flags test nonempty values. Clickable uses the captured Boolean. In-list means a strict ancestor is scrollable and has at least two immediate children with identical full subtree signatures. Same-class siblings excludes the target itself and counts only the captured parent's children; the capture root has zero siblings. Target-set size is the distinct selected-node count. Collection aggregation follows the shared rules above. |
| Relative | `rule_rank_norm` is the zero-based rule ordinal divided by group size. `rule_cost_gap` subtracts the best group cost. `group_size` is the complete verified candidate count. `family_rank_in_group` is `ln(1 + zero-based ordinal)` among the same-family candidates in rule order. Ordinals use the deterministic rule ordering, not input order. |

The prepared group returns fresh arrays so consumers cannot mutate a cached feature vector. Dataset CSV exports these values directly; Python does not recompute or reinterpret them.
