# 真实应用数据采集助手

此工具服务于路线图 P2.5 / Q8: 在真实应用中跟踪同一目标, 收集它在多个页面状态下的布局和人工确认标注。建议首轮至少 30 个应用, 每个应用至少 5 个任务, 每个任务至少 3 个不同状态。

电脑自动完成布局抓取、传输、保存、对应节点推荐、进度统计和任务导出。维护者负责打开页面、改变页面状态, 并逐个确认目标。工具中的点击选择只操作电脑上的布局示意; 任务的“期望动作”用于记录定位需求。

## 启动

Windows 可直接双击 `tools/codegen-model/collect-real.cmd`。需要 Python 3.10 或更新版本及其自带的 Tcl/Tk, 无需安装额外 Python 库。当前开发机已具备这些组件。

也可以从仓库根目录启动, 指定本次联调所用的 Sony 手机:

```powershell
.\tools\codegen-model\collect-real.cmd --private-dir D:\codegen-private --serial QV770340J7
```

启动脚本与当前工作目录无关, 放到桌面的快捷方式也可使用。私有目录选择顺序为:

1. 命令行 `--private-dir`。
2. 环境变量 `CODEGEN_PRIVATE_DIR`。
3. 已存在的 `D:\codegen-private`; 如果不存在, 使用当前用户主目录下的 `codegen-private`。

助手会为当前进程设置 `CODEGEN_PRIVATE_DIR`, 不修改系统环境变量。界面顶部始终显示实际目录。目录必须位于 Git 工作树之外, 所有导入布局也必须已经放入该目录。旧版 `label_real.py` 生成的任务会计入进度检查。

ADB 默认从 PATH、`ANDROID_HOME`、`ANDROID_SDK_ROOT` 或本仓库的 `local.properties` 查找, 也可传入 `--adb E:\.android\sdk\platform-tools\adb.exe`。没有连接设备时, 仍可导入、标注和导出已有布局。

手机需启用 USB 调试, 并允许这台电脑连接; AutoJs6 需具备无障碍服务及文件访问权限。采集使用现有 AutoJs6 的布局捕获实现, 无需重装本次开发后的 APK、Root、模型或训练依赖。

## 完成第一个任务

1. 在设备下拉列表选中手机。多设备时不会自动猜测; 手动选择会保存为下次首选设备。
2. 在手机打开目标应用和目标页面。电脑点击“新建任务”, 再点“读取手机前台包名”。也可以手动填写包名。
3. 填写能辨认意图的任务名称, 例如“更新列表中某应用的图标”。选择“单个目标”或“目标集合”, 设置期望动作和允许用于定位的属性, 创建任务。
4. 点击“采集当前手机布局”。每次点击只采集一次当前窗口, 完成后即保存到电脑。窗口必须属于任务指定的应用; 系统权限弹窗、输入法或其他应用遮挡时, 可能需要先关闭遮挡再重试。
5. 在节点列表搜索文字、ID、描述、类名或先序序号; 也可以点击右侧布局示意。选中最小范围内的节点后, 可用“选父节点”调整。集合使用 Ctrl 多选。
6. 检查下方的路径、文字、描述、父级、同级及向上两三级范围内的文字。确认确实是目标后, 点击“确认这些目标”。首个状态的变化说明可以留空。
7. 在手机改变同一页面的状态, 再采集一次。后续状态会推荐对应节点, 但列表重排、重复 ID、无文字图标等情况仍可能选错。请核对后改选, 填写“上方一行被删除”等变化说明并确认。
8. 至少保留 3 个不同布局且全部确认后, 点击“完成并导出任务”。导出成功后任务冻结, 可以查看; 后续采集其他目标或新状态时新建任务。

采集不要求连续完成。关闭再启动助手后, 左侧可以恢复已有草稿。原始布局在采集时保存; 目标选择和变化说明在点击“确认这些目标”时保存。未确认的推荐不能生成正式任务。

如果某状态采错、目标消失或暂时无法辨认, 使用“排除 / 恢复”。排除保留原始文件供复核, 导出时忽略该状态; 恢复后必须重新确认。每个状态的目标数量必须一致, 当前任务格式不支持目标消失或集合数量改变。

## 删除草稿和状态

- 选中任务后, 点击任务列表上方的“删除草稿”, 可以删除整个草稿及其全部布局和标注。
- 选中状态后, 点击状态列表下方的“删除状态”, 可以删除该状态及其布局文件。删除全部状态后, 草稿仍然存在, 可以重新采集。
- 两种删除都会先显示名称或状态编号, 由维护者确认后执行; 删除无法撤销。只想暂时不用某个状态时, 可使用“排除 / 恢复”。
- 删除只适用于未导出的草稿。已导出的任务及其状态继续保持冻结。

删除后的状态编号保持稳定, 不会重新编号或重复使用。例如删除 s1 后, 原 s2 仍为 s2, 下一次采集为 s3。旧草稿可以直接继续使用。

如果删除、排除或恢复状态使“首个有效状态”改变, 后续变化说明的比较基准也会改变。助手会清空剩余有效状态的变化说明, 使其重新进入待确认状态; 原有目标选择保留供核对。请按新的首个有效状态重新填写说明并确认, 然后再导出。

## 变化说明历史

“相对首个状态的变化”支持直接输入, 也支持从下拉框选择最近的说明。最多保留 20 条不同记录, 最近使用的排在最前面; 再次使用旧记录会将它移到最前面, 超过上限则移除最早的记录。空白输入不会加入历史。

完成输入后离开输入框、按 Enter、切换状态、开始设备操作或关闭窗口, 都会保存本次输入到历史; 确认目标时也会更新历史。历史在不同任务和下次启动时均可复用, 保存在私有目录的 `collector/preferences.json` 中。保存输入历史不会自动确认目标或保存任务标注。

## 搜索历史与高亮定位

搜索框支持直接输入和历史下拉选择, 最多保留最近 20 条不同记录。点击“搜索”、按 Enter 或选择历史记录会立即筛选; 再次使用旧记录会置顶, 超出上限则移除最早记录。离开搜索框、切换布局、开始设备操作或关闭窗口时, 尚未提交的搜索输入也会保存到历史。搜索历史与变化说明历史分别保存, 重启助手后仍可复用。

刷新“查看当前布局”、采集或导入新状态、切换已保存状态时, 搜索内容会保留, 并在新的布局树上重新筛选, 无需再次输入或点击搜索。临时查看结束后点击“返回任务”, 仍会恢复进入查看模式前的任务搜索条件。

节点列表中的蓝色高亮表示已选中的目标。点击“显示全部”会清除当前筛选, 保留目标选择, 并自动滚动到第一个高亮条目; 多次点击也会重新定位到第一个高亮。当前搜索内容仍保留在历史中。

“上一个高亮 / 下一个高亮”按节点顺序在当前可见的高亮之间循环定位, 到达两端后回到另一端, 下方详情优先显示当前定位的节点。导航只改变查看位置, 不改变选中的目标集合或已保存标注。若搜索隐藏了所有已选目标, 导航按钮会禁用; 点击“显示全部”即可恢复并定位。没有选中目标时, “显示全部”仍会正常展示所有节点。

## 临时查看手机页面

选择设备后, 点击“查看当前布局”。无需先创建或选择任务, 助手会自动识别手机的前台应用并显示当前布局。可以照常搜索、选择节点、查看布局示意、父级和相邻文字; 再次点击按钮可以刷新到手机的新页面。

临时查看的布局仅保留在电脑内存中, 不生成本地布局文件、不追加任务状态, 也不计入采集进度。手机端仍使用相同的临时传输与清理流程。在查看模式下, 采集到任务、确认目标、导出及删除等任务操作会暂时禁用。

点击“返回任务”即可继续原来的工作, 之前尚未确认的目标选择、变化说明和搜索条件会恢复。也可以从左侧列表直接选择任务或状态, 切换回相应的任务页面。

## 怎样采到有价值的状态

一组任务始终跟踪同一个目标或同一组目标, 同时让周围布局发生变化。例如:

| 页面 | 可以选择的目标 | 状态变化 |
| --- | --- | --- |
| 列表 | 某行的图标、操作按钮或标题 | 上方插入 / 删除一行, 排序变化, 进度条出现 |
| 设置或表单 | 某标签附近的开关、输入框 | 展开说明, 出现校验提示, 其他选项改变可见性 |
| 搜索结果 | 某结果的图标或操作入口 | 排序变化, 结果内容刷新, 同名项出现 |
| 详情页 | 固定操作按钮或同组入口 | 内容长度变化, 展开折叠, 文本或语言变化 |
| 导航与卡片 | 一个入口或固定数量的目标集合 | 插入卡片, 徽标变化, 标签或图标位置变化 |

可以先从熟悉的应用开始, 每个应用采集 5 种实际定位意图。重复保存未改变的页面会被拒绝; 只改变文件名或捕获时间也不算新状态。检查基于完整布局树, 能识别完全相同的树; 时钟变化等无关变化是否足够有价值, 仍需人工判断。

“输入文字”“点击”等期望动作不会由助手在手机上执行。若为制造状态变化需要操作手机, 请自行选择适合测试的页面和操作。

## 导入原有数据和查看进度

已保存的 `.layout.json` 可先复制到 `CODEGEN_PRIVATE_DIR` 下, 再选择任务并点击“导入已有布局”。批量导入按文件名排序, 请使用时间戳或 `s0`、`s1`、`s2` 等能表达正确顺序的文件名。导入会保留独立副本; 修改原文件不会改变已采集状态。

“检查采集进度”会递归检查私有目录中的 `.cgtask.json`, 汇总应用数、每个应用的完成组数、达到 5 组的应用数及草稿数。只有至少 3 个不同状态且格式有效的真实任务才计入完成数。重复任务编号、改名复制的相同任务、损坏布局和被修改的确认记录会显示为检查问题。单状态或双状态旧任务单独列为不足, 不计入 Q8 完成数。

也可以不打开窗口检查进度:

```powershell
python tools/codegen-model/capture/real_gui.py --private-dir D:\codegen-private --report
```

同一私有目录一次只能由一个助手实例写入。运行上述检查前, 请先关闭图形窗口。

## 文件及后续工具

```text
CODEGEN_PRIVATE_DIR/
  collector/
    preferences.json                 最近选择的设备、最近 20 条变化说明及最近 20 条搜索
    progress.json                    本机进度及校验问题
    groups/
      real-<唯一编号>/
        session.json                 草稿、目标确认时间及设备/应用版本信息
        snapshots/*.layout.json      原始布局
        task.cgtask.json              完成后导出的 format 1 真实任务
```

任务使用现有 `source: real` / `.cgtask.json` 契约, 可以由 `TaskGroup`、候选导出和 `RealGroupDiagnosticsTask` 直接读取。给后续工具指定 `CODEGEN_PRIVATE_DIR\collector\groups` 即可递归读取新任务; 原有任务目录可继续单独使用。助手不运行模型评估或训练, 不打开预留留出集, 不改变真实数据默认用于 `real-test` 的现有约定。后续离线诊断步骤见 [工具总说明](../README.md#diagnose-labelled-real-groups-offline)。

电脑端临时文件也放在私有目录。手机端的启动脚本和配置短暂放在 `Download/autojs6-codegen-bootstrap/<本次编号>`; 它们让 AutoJs6 自己创建可访问的应用目录, 避免部分设备上 ADB 创建的目录被拒绝访问。原始布局临时保存在 AutoJs6 自身的 `Android/data/org.autojs.autojs6/files/codegen-real/<本次编号>` 内, 传回并校验后释放; 退出助手会等待工作脚本停止并清理本次协议文件。仍在运行的手机脚本在闲置 2 分钟后自行退出并删除待传输布局。强制杀死手机进程或设备断电会阻止退出清理, 此时可以在设备恢复后检查上述本次编号目录。所有清理仅限本次创建的文件。

## 常见问题

| 提示或现象 | 处理方式 |
| --- | --- |
| `unauthorized` / `offline` | 解锁手机, 确认 USB 调试授权, 检查连接后刷新设备 |
| 找不到 ADB | 用 `--adb` 指定 Android SDK 的 `platform-tools/adb.exe` |
| 采集脚本未就绪 | 查看 AutoJs6 提示和脚本日志, 检查文件访问权限 |
| 页面应用与任务不同 / 无法读取当前窗口 | 返回任务指定的应用, 关闭遮挡, 检查 AutoJs6 无障碍服务 |
| 布局完全相同 | 先改变页面内容或结构, 再采集; 重试不应凑作新状态 |
| 推荐错位 | 按文字、ID 或描述搜索, 对照父级和邻近文字手动改选 |
| 每个状态目标数量必须一致 | 重新核对集合, 或排除目标消失/数量变化的状态 |
| 已导出并冻结 | 新建另一任务; 原始采集与已确认导出保持可复核 |
